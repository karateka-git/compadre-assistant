# Черновик описания PR: личный выбор возможностей

Этот текст предназначен для проверки перед созданием PR в `main`. Фактические
URL, SHA и CI добавляют после публикации ветки; текущие локальные результаты
записаны в [PLAN.md](PLAN.md#проверка-шага-52--21102026). Допуск merge и
релиза определяется [RELEASES.md](../RELEASES.md), а порядок живой приёмки —
в [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).

## Что меняется

- Для одного `AppUser` сохраняется личный выбор встроенных Ask и Obsidian.
  Отсутствующая настройка означает Ask включён, Obsidian выключен, включая
  прежних пользователей.
- `/capabilities`, `/enable <id>`, `/disable <id>` управляют доступом во всех
  связанных Telegram/VK-каналах. Серверный `ENABLED_CAPABILITIES` остаётся
  верхней границей; личная команда не собирает отключённый на сервере runtime.
- `0002_user_capability_preferences.sql` добавляет отдельную таблицу с FK на
  `AppUser`. Существующие статьи, vault, identities и режимы не удаляются.
- Общие ответы и маршрутизация учитывают личный выбор. Уже допущенная
  длительная операция может закончиться после disable; следующий вход
  проверяет новое состояние. Ревизия режима сохраняет действие `/exit` и
  последующей смены режима.
- Постоянные инструкции обновлены; временные материалы остаются до живой
  приёмки и завершающего удаления по `AGENTS.md`.

## Риск и выпуск

Прежний пользователь Obsidian без явной личной настройки должен отправить
`/enable obsidian`, чтобы продолжить работу в сохранённом режиме. Данные
остаются. Для Ask нужен серверный `ENABLED_CAPABILITIES` с `ask` и действующий
профиль провайдера. Версию и release notes выбрать отдельно; установку VPS
и живые сценарии выполнять только по [checklist](RELEASE_CHECKLIST.md).
