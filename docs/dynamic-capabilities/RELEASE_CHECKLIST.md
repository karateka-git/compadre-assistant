# Выпуск и живая приёмка личных возможностей

Этот checklist ведёт функцию от feature worktree до подтверждённых ответов
Telegram/VK после установки версии. Правила допуска находятся в
[RELEASES.md](../RELEASES.md), команды установки и восстановления — в
[OPERATIONS.md](../OPERATIONS.md), последний датированный снимок сервера — в
[PRODUCTION.md](../PRODUCTION.md). Локальные результаты и команды шага 5.2
зафиксированы в [PLAN.md](PLAN.md#проверка-шага-52--21102026).

На 21.10.2026 выполнены локальные проверки из плана, включая image build и
healthcheck candidate SHA `1b4b64d599d79c3e19362994ea961bbc5d89e055`.
Полный CI точного merge SHA всё равно обязателен.
PR, опубликованный SHA, Release, установка и живые ответы этой функции ещё
не проверены. Поля ниже заполняют только после наблюдения фактического
результата; версия `vX.Y.Z`, номера PR и SHA здесь являются шаблонами.

## 5. Установить и проверить результат контроллера

- [ ] В согласованном окне выполнить на VPS `sudo deploy-prod vX.Y.Z` с
  **фактической** утверждённой версией. Контроллер сам делает проверенную
  backup-копию, останавливает оба writer, применяет недостающую `0002` и
  проверяет candidate. Не запускать миграцию вручную параллельно каналам.
- [ ] Записать безопасные доказательства: `stage=success`, `last_good`
  version/SHA, отсутствие marker, backup verified ID/время,
  `schema_migrations` содержит `0001` и `0002`, `integrity_check=ok`,
  `foreign_key_check` пуст, два контейнера на ожидаемом image ID и `healthy`,
  polling обоих каналов, активные service и backup timer. Не включать
  содержимое SQLite, токены, PEM и полные логи в отчёт.
- [ ] Если контроллер завершился отказом, записать stage и следовать
  [матрице восстановления](../OPERATIONS.md#отказ-выпуска-и-возврат).
  При `degraded` оставить marker и writer в безопасном состоянии; нельзя
  считать локальные тесты основанием для автоматического восстановления.

Установка считается технически завершённой только после сверки фактического
SHA/image, схемы, backup и обоих каналов. Это ещё не живая приёмка.

## 6. Провести живую приёмку связанных каналов

Использовать согласованные тестовые Telegram/VK identities одного `AppUser A`
и отдельного `AppUser B`. Перед началом записать дату, версию, SHA, каналы и
псевдонимы профилей без публикации внешних ID и текстов вопросов:
`________________`. Если канал ещё не связан, выполнить `/link_code` и
`/link <код>` по [RUN.md](../RUN.md#13-посмотреть-доступные-команды), затем
сверить профиль назначения; rebind другого профиля не делать случайно.

- [ ] Сразу **после deploy, до переключения** снять для обоих контейнеров
  container ID, image ID, PID и `StartedAt` безопасной read-only командой:

  ```bash
  cd /opt/obs-chat-bot
  for service in tg_assistant vk_assistant; do
    cid=$(docker compose ps -q "$service")
    docker inspect --format '{{.Name}} {{.Id}} {{.Image}} {{.State.Pid}} {{.State.StartedAt}}' "$cid"
  done
  ```

- [ ] A: `/capabilities` в Telegram и VK показывает одинаковый личный выбор.
  B: снять собственный `/capabilities` до действий A. Доказательство:
  `________________`.
- [ ] A: `/enable obsidian` в Telegram подтверждён после commit; VK
  показывает Obsidian включённым. A входит `/obsidian` в Telegram;
  `/status` этого чата показывает режим `obsidian`. Доказательство:
  `________________`.
- [ ] A: `/disable obsidian` в VK подтверждён. Следующий обычный текст в
  Telegram получает подсказку включения, не предметный ответ; `/status`
  по-прежнему показывает сохранённый режим. B повторно получает свой прежний
  `/capabilities`. Доказательство: `________________`.
- [ ] A: `/enable obsidian` в VK. Следующий безопасный текст в исходном
  Telegram-чате снова идёт в сохранённый режим; при наличии заранее
  согласованной сохранённой статьи проверить её доступность без записи в
  GitHub. Доказательство режима и сохранённых данных: `________________`.
- [ ] A: начать достаточно долгий `/ask <тестовый вопрос>` в Telegram и
  **после ранней квитанции, до результата** отправить `/disable ask` в VK.
  Итоговый ответ должен прийти в исходный Telegram-чат; следующий `/ask`
  получает отказ без вызова модели. Если модель ответила до disable,
  гонка не доказана — повторить сценарий в согласованном окне. Записать
  порядок timestamps без текста вопроса/ответа: `________________`.
- [ ] Повторить read-only `docker inspect` для двух контейнеров и сравнить
  container ID, PID, `StartedAt` и image ID со снимком до переключений.
  Они должны совпадать: личные команды не перезапускают каналы. Доказательство:
  `________________`.
- [ ] Получить явное подтверждение пользователя для Telegram, VK, изоляции B,
  фонового ответа, сохранения данных и отсутствия рестарта. Кто/когда/какие
  пункты подтвердил: `________________`.

При отсутствии настроенного Ask или безопасного тестового профиля сценарий
не заменяют локальным fake-тестом: записать препятствие и оставить живую
приёмку открытой. Device Flow после disable проверен локально; его живой
повтор не должен отключать действующий продуктивный vault ради теста.
