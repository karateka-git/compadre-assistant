# Рефакторинг документации

Временный рабочий каталог функциональности. Сохранить его до завершения всех этапов и эксплуатационной приёмки. Перед закрытием перенести действующие правила в постоянные документы, проверить ссылки и удалить каталог отдельным завершающим изменением.

## План

1. Переписать `docs/RELEASES.md` для чтения по шагам: маршрут, проверки, версия, публикация, установка, исправления и аварийный выпуск.
2. Сверить каждое действующее условие с исходным документом и связанными эксплуатационными инструкциями.
3. Провести review текста и при необходимости уточнить его без изменения процесса выпуска.
4. Выделить приёмы из обновлённого `RELEASES.md` в постоянные правила документации.
5. Пройти все постоянные файлы `docs/`: улучшить навигацию и подачу по правилам документации, сохранив факты, команды, условия и исторические записи.
6. Сверить ссылки, противоречия между документами и итоговый diff. Исправить найденные несоответствия до закрытия этапа.
7. Удалить исторические журналы и аудит после сверки действующих сведений с кодом; сохранить краткие причины решений, текущий снимок VPS и открытые задачи в профильных документах.

## Решения

- Схемы показывают обычный маршрут и точки полного CI; подробные команды остаются в `docs/OPERATIONS.md`.
- Все существующие ограничения, исключения и ссылки на эксплуатационный runbook сохранены. Новых правил выпуска этот этап не вводит.
- Фактическое состояние VPS остаётся в `docs/PRODUCTION.md`, чтобы описание процесса не устаревало вместе с очередным развёртыванием.
- Общие правила оформления находятся в `docs/DOCUMENTATION_GUIDELINES.md`; временный каталог хранит только ход текущей работы.

## Рабочие материалы

- Исходник для сверки: `docs/RELEASES.md` в `main` на момент начала работы.
- Перекрёстные документы: `docs/OPERATIONS.md`, `docs/PRODUCTION.md`, `AGENTS.md`.
- Проверка: сопоставление разделов и Git diff; тесты приложения для правки Markdown не требуются.
- Прежнее решение сохранить полные `HISTORY.md` и `DECISIONS.md` пересмотрено по запросу пользователя: архивных копий и `CHANGELOG.md` не создаём. История опубликованных версий доступна в GitHub Releases; прежние редакции документов доступны в истории Git.
- Обход постоянных файлов `docs/` завершён: в инструкциях усилены маршрут и условия действий, в бэклоге — тематический указатель. Исторические журналы удалены после сверки; `RELEASES.md` и `DOCUMENTATION_GUIDELINES.md` подготовлены на предыдущих шагах.
- При общей сверке устранено противоречие о проверке Docker exit code: `scripts/common.ps1` действительно проверяет `$LASTEXITCODE` после каждого `Invoke-ProjectCompose`.
