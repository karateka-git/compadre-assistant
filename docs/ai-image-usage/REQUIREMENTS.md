# Требования к режимам ИИ и администрирования

Требования описывают, как в Telegram и VK задать вопрос модели, получить
текст с изображения и посмотреть общие расходы на эти запросы. Действующая
маршрутизация описана в [архитектуре](../ARCHITECTURE.md#как-проходит-сообщение)
и [правилах пользовательских сообщений](../USER_MESSAGES.md#выбрать-ответ-по-состоянию-чата).
Порядок разработки и проверки описан в [плане реализации](IMPLEMENTATION_PLAN.md).

## Работа с ИИ

| Действие | Поведение |
| --- | --- |
| `/ai` | Войти в режим ИИ в текущем чате и увидеть доступные действия. |
| `/ask [вопрос]` | Задать один текстовый вопрос модели без истории переписки. Если вопрос не указан, бот просит прислать его следующим сообщением. |
| `/get_text_from_image` | Запустить ожидание одного фото или скриншота. После получения изображения бот возвращает распознанный текст. |
| `/exit` | Выйти из активного режима текущего чата. |

Команду внутри режима можно выполнить, когда этот режим уже активен в
текущем чате и у пользователя есть доступ к нему. Это действует и при ручном
вводе, и при нажатии кнопки. `/ask` доступна только после явного входа через
`/ai` в текущем чате. Если режим ИИ не активен, бот подсказывает `/ai`, когда
пользователю доступен вход. После ответа на вопрос режим ИИ остаётся активным.

После `/get_text_from_image` фото можно отправить без подписи. Бот сохраняет
язык, порядок и переносы строк оригинала, помечает неразборчивые места
и сообщает, если текста нет. До вызова команды фото в `/ai` вызывает
подсказку с `/get_text_from_image`. Запрос к модели начинается только после
явного запуска сценария и получения изображения. При отмене или истечении
ожидания бот предлагает начать сценарий заново.

## Администрирование

`/admin` открывает отдельный режим для доверенных пользователей. Изначально
право есть у владельца проекта. Бот проверяет доступ к режиму при входе и
при выполнении его команд, в том числе после отзыва доступа в уже открытом
режиме. Режим отображается в меню только тем, кому он доступен. Вход и отчёт
доступны только в личных чатах Telegram и VK.

В активном режиме `/admin` команда `/llm_costs [DAY|MONTH|YEAR] [часовой_пояс]`
показывает расходы выделенного ключа AI Gateway по официальной статистике
Timeweb Cloud. Все модели, использованные через этот ключ, входят в отчёт.
Суммы указаны в валюте аккаунта, с учётом скидок и до списания бонусов.

- Без периода `/llm_costs` и кнопка отчёта показывают текущие сутки, месяц
  и год. По умолчанию применяется `Asia/Omsk`.
- `/llm_costs DAY`, `/llm_costs MONTH` и `/llm_costs YEAR` выбирают один период.
- `/llm_costs Europe/Moscow` строит отчёт по московскому времени для этого вызова.
- Аргумент передаётся как идентификатор IANA и проверяется через
  `zoneinfo.ZoneInfo`. При неизвестном значении бот объясняет ошибку и
  показывает пример команды.

Для запроса отчёта вычисляем начало выбранного периода в местном поясе и
переводим границы в UTC. При неполном покрытии, в том числе если начало
периода выходит за подтверждённые 90 суток, бот сообщает, что полный период
недоступен. При известной стоимости только части интервалов сумма
помечается как частичная. Ноль допускается при подтверждённой нулевой сумме
или нулевой длительности периода. Сбой при чтении одного периода оставляет
другие строки сводки. Без настроенного API команда сообщает об этом.
[Метод статистики](https://github.com/timeweb-cloud/sdk-go/blob/main/docs/AIGatewayAPI.md#GetAiKeyTokenUsageStatistic) ·
[Окно статистики Timeweb](https://timeweb.cloud/docs/ai-gateway/usage-statistics).

## Учёт расходов

Учёт общий для проекта и охватывает текстовые вопросы и распознавание
изображений в Telegram и VK. Стоимость каждого обращения сохраняется в фоне.
Ответ пользователю содержит результат запроса к модели.

Запись в SQLite хранит время обращения, фактически ответившую модель,
доступные счётчики токенов, использованный тариф и расчётную сумму.
Если модель сообщила расход, учитываем его и при непригодном для выдачи ответе.
Привязка к пользователю и содержимое запроса или ответа для отчёта не нужны.
Локальная история накапливается с момента включения учёта. Отчёт Admin
использует статистику Timeweb.

В Timeweb AI Gateway `usage` содержит счётчики токенов. Расчёт опирается на
тарифы модели, включая особенности тарификации кэша и других типов токенов,
когда провайдер даёт нужные данные. Точное списание по каждому запросу
в публичном API не предусмотрено. В панели Timeweb можно сверять оценку
с логами запросов и статистикой за последние 90 дней. Цена в логе может
отличаться от списания с баланса.
[Ответ команды Timeweb о тарифах и API](https://timeweb.cloud/docs/ai-gateway) ·
[Логи запросов](https://timeweb.cloud/docs/ai-gateway/logs) ·
[Статистика](https://timeweb.cloud/docs/ai-gateway/usage-statistics)
