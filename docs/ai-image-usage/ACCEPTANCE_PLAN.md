# План этапа 6. Приёмка и завершение документации

Этап проверяет режимы ИИ и администрирования в личных чатах Telegram и VK,
фиксирует результаты и сохраняет действующие сценарии в постоянной
документации. Правила функций описаны в [требованиях](REQUIREMENTS.md), порядок
проверок и выпуска — в [инструкции запуска](../RUN.md#проверка-изменения-кода)
и [маршруте выпуска](../RELEASES.md#маршрут-выпуска).

### Подготовить источник и сверить статистику

1. Сверить SHA архива, образ, проект, mount тестовой БД и фильтр личных
   событий. Подготовить через согласованный секретный канал конфигурацию
   доступа, сверить UUID общего ключа шлюза, право токена Timeweb Cloud
   читать статистику этого ключа и код валюты аккаунта. В обоих тестовых
   контейнерах задать `ADMIN_TIMEWEB_API_TOKEN`, `ADMIN_TIMEWEB_KEY_ID`
   и `ADMIN_TIMEWEB_CURRENCY`. Запросы Ask и OCR в обоих каналах направить
   через этот же ключ. Секреты и идентификаторы пользователей в протокол
   не вносить. [Настройка и контракт API](ADMIN_PLAN.md#6-добавить-адаптер-статистики-и-настройки-timeweb).
2. На стенде последовательно выполнить Ask и OCR из обоих каналов. Записать
   время действий в UTC, модель и появление новых записей локального учёта.
   Сопоставить время запросов с обновлением статистики общего ключа.
   Сверить API с панелью Timeweb для одинаковых границ, где панель
   позволяет их задать. Проверить сетку часовых меток UTC от часа начала
   до часа переданного конца включительно, в том числе для пустых и
   неполных часовых интервалов. Сверить `meta.total` и суммы `total_cost`
   до списания бонусов. Зафиксировать наблюдаемую задержку обновления данных.
3. В двух личных чатах открыть `/admin`, вызвать сводку и каждый период
   отдельно. Сопоставить значения с API того же ключа за те же UTC-границы
   и на одном снимке данных. Проверить результат в `Asia/Omsk` и
   `Europe/Moscow`, недопустимый IANA-ключ и подтверждённое покрытие
   90 суток. Если начало `YEAR` старше 90 суток, проверить явный статус
   недоступного полного года при сохранении доступных суток и месяца.
4. Проверить на тестовом профиле ответ без настроек API и при сбое
   источника. Для живого неполного либо пустого ответа записать фактический
   результат. Если API такого ответа в тестовом окне не возвращает,
   сослаться на проверку с подставным HTTP и явно указать её охват.
   Подтверждённый ноль должен отличаться от отсутствующей цены и
   неполного покрытия. Доступ и отзыв проверить по матрице ниже.

### Проверить команды в личных чатах

Владелец использует доверенный профиль в двух привязанных личных чатах.
Отдельный обычный профиль используется для отрицательной проверки после
согласования его личного адреса.

| Сценарий в каждом канале | Наблюдаемый результат |
| --- | --- |
| Состояние после `/exit`, затем `/ask <вопрос>` | Бот предлагает войти через `/ai`. Обращения к модели нет. |
| `/ai`, затем прямой и пошаговый `/ask` | Ответ приходит в исходный чат. Режим сохраняется. Вход в одном канале не открывает режим в другом. |
| Справка, меню, кнопка и ручная команда | Команды соответствуют режиму. Старую кнопку после выхода обработчик отклоняет. |
| Фото в `/ai` без ожидания | Бот предлагает `/get_text_from_image`. Обращения к модели нет. |
| `/get_text_from_image`, затем синтетическое фото с известным многострочным текстом | Текст приходит в исходный чат. Сверены строки, порядок и внешний вид в реальном клиенте. |
| Приём фото и `/cancel` во время распознавания | Квитанция приходит до результата. Бот подтверждает отмену, отменённый результат в чат не приходит. |
| Ожидание, `/cancel`, затем фото | Бот предлагает начать сценарий заново. Обращения к модели нет. |
| `/llm_costs` вне `/admin`, затем вход доверенного профиля | Вне режима отчёт не выдаётся. В режиме доступны ручная команда и кнопка. |
| `/llm_costs`, `/llm_costs DAY`, `/llm_costs MONTH Europe/Moscow`, `/llm_costs YEAR` | Сводка и отдельные периоды совпадают с подтверждённой статистикой ключа Timeweb для тех же границ. Отчёт показывает пояс, валюту и статус неполного или недоступного периода, если применимо. |
| Неверный IANA-пояс, отсутствие конфигурации, пустой или неполный ответ API | Бот даёт подсказку или объясняет недоступность либо неполноту. Неподтверждённая стоимость не отображается как ноль. |
| Обычный профиль и отзыв доступа доверенному профилю | Вход и команда отклоняются. После запуска с обновлённым списком режим скрывается из меню, сохранённый режим и старая кнопка отчёт не открывают. |
| Общая статистика Telegram и VK | Оба чата показывают итог по тому же UUID и за те же границы, что и API Timeweb. Локальная SQLite подтверждает запись каждого последовательного запроса Ask и OCR. |

Записать ожидание, наблюдение и результат каждого сценария. Для SQLite
сопоставить изменение числа записей с интервалами выполнения последовательных
действий. Число записей используется для проверки фонового учёта Ask и OCR.
Суммы отчёта сверяются по API Timeweb.

После успешной проверки сверить границы ресурсов тестового проекта и
удалить его контейнеры и тестовый файл SQLite с sidecar-файлами по
согласованию пользователя. Записать результат очистки в протокол.

**Готово, когда** записаны результаты Ask и OCR в обоих каналах, сводка
и каждый доступный период `DAY`, `MONTH` и `YEAR` сверены с API по тому же
UUID общего ключа, а ограничения полноты подтверждены в отчёте.
