   Сопоставить время запросов с обновлением статистики общего ключа.
   Сверить API с панелью Timeweb для одинаковых границ, где панель
   позволяет их задать. Проверить сетку часовых меток UTC от часа начала
   до часа переданного конца включительно, в том числе для пустых и

   `interval=60` отдельно прочитать `/api/v1/cloud-ai/ai-keys/statistic/calls`.
   Сверить часовую сетку и `meta.total`, затем сложить `call_count`.
   Проверить период с известными тестовыми запросами и окно без запросов.
   Зафиксировать UTC-границы, суммы и наблюдаемую задержку обновления данных.

### Проверить команды в личных чатах

Владелец использует доверенный профиль в двух привязанных личных чатах.
Отдельный обычный профиль используется для отрицательной проверки после
согласования его личного адреса.

| Сценарий в каждом канале | Наблюдаемый результат |
| --- | --- |
| Состояние после `/exit`, затем `/ask <вопрос>` | Бот предлагает войти через `/ai`. Обращения к модели нет. |
| `/ai`, затем прямой и пошаговый `/ask` | Ответ приходит в исходный чат. Режим сохраняется. Вход в одном канале не открывает режим в другом. |
| Справка, меню, кнопка и ручная команда | Команды соответствуют режиму. Старую кнопку после выхода обработчик отклоняет. |
| Фото в `/ai` без ожидания | Бот предлагает `/get_text_from_image`. Обращения к модели нет. |
| `/get_text_from_image`, затем синтетическое фото с известным многострочным текстом | Текст приходит в исходный чат. Сверены строки, порядок и внешний вид в реальном клиенте. |
| Приём фото и `/cancel` во время распознавания | С квитанцией появляется меню только с `/cancel`. Бот подтверждает отмену, отменённый результат в чат не приходит. После отмены и после обычного результата возвращается меню режима `/ai`. |
| Ожидание, `/cancel`, затем фото | Бот предлагает начать сценарий заново. Обращения к модели нет. |
| `/llm_costs` вне `/admin`, затем вход доверенного профиля | Вне режима отчёт не выдаётся. В режиме доступны ручная команда и кнопка. |
| `/llm_costs`, `/llm_costs DAY`, `/llm_costs MONTH Europe/Moscow`, `/llm_costs YEAR` | Стоимость и число запросов совпадают с подтверждённой статистикой Timeweb для ключа и границ периода. Отчёт показывает пояс, валюту и статус неполного или недоступного периода, если применимо. |
| Неверный IANA-пояс, отсутствие конфигурации, пустой или неполный ответ API | Бот даёт подсказку или объясняет недоступность либо неполноту. Ноль выводится для подтверждённой статистики либо периода нулевой длительности. При сбое одного метода API доступный показатель сохраняется. |
| Обычный профиль и отзыв доступа доверенному профилю | Вход и команда отклоняются. После запуска с обновлённым списком режим скрывается из меню, сохранённый режим и старая кнопка отчёт не открывают. |
| Общая статистика Telegram и VK | Оба чата показывают итог по тому же UUID и за те же границы, что и API Timeweb. Локальная SQLite подтверждает запись каждого последовательного запроса Ask и OCR. |

Записать ожидание, наблюдение и результат каждого сценария. Для SQLite
сопоставить изменение числа записей с интервалами выполнения последовательных
действий. Число записей используется для проверки фонового учёта Ask и OCR.
Суммы и число запросов отчёта сверяются по API Timeweb.
Обычное меню другого чата во время распознавания проверить локальным тестом.

**Готово, когда** записаны результаты Ask и OCR в обоих каналах, сводка
и каждый доступный период `DAY`, `MONTH` и `YEAR` сверены с API по тому же
UUID общего ключа для обоих показателей. Ограничения полноты подтверждены в отчёте.

На `v4.0.0` в живом VK владелец увидел отдельное сообщение
«Меню команд обновлено.» при переходах сценария и кнопку `/cancel` во время

В Telegram владелец увидел технический ID `ask` в отказе `/ai` и
подтверждении `/enable ask`.

1. [x] **Доставить постоянную клавиатуру VK с ответом.** При изменении меню
   текущего чата приложить постоянную клавиатуру к подходящей части обычного
   ответа или квитанции. Для обычного ответа с такой частью отдельное
   «Меню команд обновлено.» не отправляется. Если нужны обе клавиатуры,
   сохранить inline-действия на своей части многочастного ответа. Адресную
   публикацию меню использовать, когда подходящего ответа нет: при сверке
   меню по адресу, обновлении связанного чата или если единственная часть
   уже несёт inline-клавиатуру. Повторять неуспешную
   публикацию с прежним `random_id`. Считать меню доставленным после успеха
   отправки и проверять его актуальность при конкурирующих обновлениях.
   Сохранить проверку личного адреса, допуск и привязку inline-действий.
2. [x] **Оставить отмену при ожидании и сделать принятый вопрос отменяемым.**
   Сразу при ожидании вопроса после `/ask` или фото после
   `/get_text_from_image` показывать только `/cancel`. Сохранить текущие
   правила меню ожидания остальных возможностей. Направить `/ask <вопрос>` и
   вопрос из пошагового ввода в общий механизм фоновых действий, уже
   используемый OCR. После валидации зарезервировать действие для текущего
   профиля и адреса, отправить квитанцию и освободить обработчик чата до
   запроса к модели. Во время выполнения оставить в меню только `/cancel`.
   Перед доставкой повторно проверить отмену, владельца и активный режим.
   После отмены, результата или ошибки восстановить меню по текущему
