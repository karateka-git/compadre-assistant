# Проверка контракта Timeweb AI Gateway

Этот документ разбивает [первый этап реализации](IMPLEMENTATION_PLAN.md#1-проверить-контракт-timeweb-ai-gateway)
на проверки для адаптера извлечения текста и первоначальной сверки стоимости.
Шаги фиксируют ход пробы. Действующий источник сумм отчёта описан в
[плане администрирования](ADMIN_PLAN.md#7-переключить-команду-и-проверить-доступ-в-обоих-каналах).

## 1. Подготовить локальную проверку

**Статус.** Выполнено в `bf1b2b3`.

Сверить по документации Timeweb идентификатор Gemini 3.1 Flash-Lite,
метод API и формат передачи изображения. Сверить, совместим ли этот метод с
действующим [профилем Ask](../SETUP.md#настройка-ask). Проверить доступность
настроек и ключа Timeweb для локального вызова, выводя только признаки их
наличия. Подготовить небольшое синтетическое изображение с известным текстом
на нескольких строках и ожидаемый результат распознавания.

**Готово, когда** известны метод, идентификатор модели и способ передачи
изображения, а тестовое изображение и ожидаемый текст доступны для вызова.
Доступность ключа отмечена отдельно. Если подходящего ключа нет, результаты
сверки можно сохранить, а живые вызовы продолжить после появления ключа.

## 2. Выполнить текстовый запрос

**Статус.** Выполнено в `c6bc639`.

Использовать конфигурацию из шага 1. Отправить короткий вопрос с ожидаемым
ответом. Зафиксировать время UTC, код ответа, возвращённую модель, доступный
идентификатор обращения и расположение полей `usage`. Указать, откуда взят
каждый идентификатор и какие сведения API не возвращает. При ошибке записать
код и обезличенную причину, устранить причину перед пробой изображения.

**Готово, когда** текстовый запрос успешен, полученный ответ проверен, а
поля для сравнения с запросом изображения зафиксированы.

## 3. Выполнить запрос с изображением

**Статус.** Выполнено в `415cdb5`.

После успешного текстового вызова отправить подготовленное изображение в ту
же модель и проверить ответ по ожидаемому тексту. Записать фактически
использованные MIME-тип и представление изображения, возвращённую модель,
идентификатор обращения, время UTC и поля `usage`, включая доступную
детализацию токенов. Сравнить форму ответа и счётчики с текстовым вызовом.

**Готово, когда** модель вернула ожидаемый текст с изображения, а формат
вызова и ответа описан по наблюдениям. При отказе API проверить формат по
документации. Если модель и API не принимают корректное изображение,
согласовать рабочую связку и повторить проверку до закрытия этапа.

## 4. Сверить обращения и определить условия расчёта

**Статус.** Выполнено в `6b32460`. Ограничения доступа к журналу и применимости ставок записаны в результатах.

Использовать наблюдения из шагов 2 и 3. Попробовать найти оба обращения в
журнале Timeweb по идентификатору или по сочетанию времени, модели и
доступных счётчиков. Записать, как подтверждена связь. Если журнал или
однозначное совпадение недоступны, указать причину и перечислить, что можно
проверить по ответам API.

Для фактически ответившей модели записать источник и дату проверки тарифа,
валюту, единицу тарификации и правила для входных, выходных, кэшированных
и других возвращённых типов токенов. Указать, входят ли детальные счётчики
в общие, если это установлено источником. Составить пример расчёта на
наблюдавшихся данных, если их достаточно, и описать случаи неизвестной
стоимости. Сумму из журнала отмечать отдельно от расчётной оценки и
фактического списания.

**Готово, когда** зафиксирован результат сверки обоих обращений и понятно,
какие поля и тарифы дают оценку, а при каких пропусках оценка неизвестна.

## 5. Подготовить материалы для следующих этапов

**Статус.** Выполнено в `57240e2`.

Собрать результаты шагов 1–4 и обезличенные примеры текстового и
мультимодального ответов. Сохранить форму полей и различия между
отсутствующими значениями и нулями. Заменить идентификаторы, удалить
credentials, заголовки авторизации и содержимое, кроме синтетического текста.
Отметить источник каждого примера и отдельно пометить искусственно
добавленные случаи для тестов, если такие примеры понадобятся.

**Готово, когда** на основе записи можно воспроизвести проверку изображения,
подготовить тестовые данные для адаптера и определить, когда рассчитывать
расход. Отсутствие доступа к журналу допустимо при зафиксированном
ограничении. Успешная проверка запроса с изображением обязательна для
закрытия этапа.
