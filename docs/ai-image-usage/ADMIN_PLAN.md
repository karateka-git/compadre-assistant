# План этапа 5. Режим администрирования и отчёт

Этап открывает доверенным профилям режим `/admin` и выдаёт отчёт `/llm_costs`
в личном чате. Шаги 1–4 фиксируют первую реализацию на локальном учёте.
Шаги 5–8 переводят отчёт на статистику Timeweb и добавляют выбор периода.
Правила команд описаны в [требованиях](REQUIREMENTS.md#администрирование),
порядок проверок — в [инструкции запуска](../RUN.md#проверка-изменения-кода).

**Статус этапа.** В работе. Выполнены шаги 1–4, ожидается переход на Timeweb.

## 1. Добавить ограничение доступа по профилю приложения

**Статус.** Выполнено в `27b41bb`. Проверены права профиля, скрытие режима, отзыв, кнопки, привязка и разбор списка доверенных ID.

- Расширить общий реестр правилом допуска для отдельной возможности. Ядро
  применяет его к разрешённому `AppUser.id` и личному выбору в каждом событии.
  Публичные возможности сохраняют текущие defaults и поведение. Покрыть вход,
  команду режима, обычный ввод в сохранённом режиме, меню, `/help`, каталог,
  прямые и пошаговые `/enable` и `/disable`, общий контекст кнопок и его
  повторную проверку. Отказ по доверенному доступу не предлагает `/enable`.
- Для `admin` использовать операторский список положительных внутренних ID
  в `ADMIN_TRUSTED_APP_USER_IDS`. Первоначально оператор указывает только
  профиль владельца. При пустом списке доступ закрыт, ошибочный формат
  отклоняется при включённой возможности. При смене списка перезапускаются
  оба процесса каналов. Проверка в новом процессе блокирует сохранённый
  режим после отзыва. Оба привязанных канала используют один `AppUser.id`.
- Определять ID владельца по точной паре из `external_identities.channel`
  и `external_identities.external_user_id` в активной базе через операторскую
  проверку только для чтения. Описать её в шаге 4, включая сверку, что
  привязанные каналы разрешаются в один профиль. Значение по умолчанию для
  ID владельца отсутствует. Username, имя чата и peer ID не дают права.
- Проверить на тестовой возможности, что изменение политики с сохранённым
  режимом блокирует новые команды и старые кнопки. Личное включение и запись
  предпочтения сами по себе недействительны без доверия. После возврата
  доверия учитывается ранее сохранённый личный выбор.

**Готово, когда** общий диспетчер применяет доверенную границу и личный
выбор независимо, а обычные возможности проходят существующие проверки.

## 2. Рассчитать календарные границы отчёта

**Статус.** Выполнено в `b0a8ba7`. Проверены Омск и Москва, смещения при переходе времени, нижние и верхняя границы в SQLite. На Windows проверен источник IANA из `tzdata`.

- В domain новой возможности принимать идентификатор IANA и один момент
  времени UTC. Использовать `Asia/Omsk` для вызова без аргумента. Зона действует
  для текущего вызова. Добавить закреплённую зависимость `tzdata` для окружений
  без системной базы IANA, включая Windows.
- Для сегодня, текущего месяца и года вычислить три локальных полуночи в
  `ZoneInfo` и перевести их в UTC. Передать полуоткрытые интервалы с общей
  верхней границей времени отчёта в один вызов `UsageTotalsReader.read_totals`.
  Вернуть пояс, точные суммы в нанорублях и количество обращений без оценки.
  Чтение выполняется через публичные контракты учёта.
- Проверить границы на фиксированном времени в `Asia/Omsk` и `Europe/Moscow`,
  переход месяца и года вблизи полуночи, зону с переходом времени, значение на
  каждой нижней границе и исключение верхней. Проверить пустую историю,
  неизвестную стоимость и недопустимый пояс. На временной SQLite использовать
  миграции и публичный API учёта для подтверждения точных границ.

**Готово, когда** один снимок даёт три точных агрегата в выбранном поясе
и проверка неизвестного пояса не вызывает чтение.

  личный чат и исключить из ответа суммы, количество запросов и детали ошибки.
  Команды внутри режима вызываются отдельно от `/admin`.
- Вывести расчётную сумму в рублях за каждый интервал, округлив итог до
  копеек из точного целого без `float`. Отдельно показать число обращений без

  `/llm_costs Europe/Moscow`. Сбой чтения должен дать короткий ответ о
  недоступности отчёта, сохранить режим и зарегистрировать ошибку для
  диагностики.
- Зарегистрировать `admin` в `ENABLED_CAPABILITIES` через существующую

  allowlist, проверку конфигурации, обработчики запуска Telegram и VK и
  сборку без `ask`. Отчёт о накопленной истории доступен с `admin` без
  клиента LLM и его credentials.
- Пройти тесты адаптеров Telegram и VK на общей временной базе. Проверить
  владельца в обоих привязанных профилях, другого и незарегистрированного
  пользователя, вызов вне режима и из группы, независимость режимов чатов,
  прямой ввод и кнопки, отзыв права в сохранённом режиме. Для отказов
  убедиться, что агрегаты не читаются. Проверить команды и меню после
  отзыва, неправильный аргумент и пустой отчёт.

**Готово, когда** доверенный профиль в активном `/admin` получает отчёт
в исходном личном чате Telegram или VK, а недопущенные вызовы завершаются
до чтения агрегатов.

## 5. Определить календарные периоды и результат отчёта Timeweb

**Статус.** Ожидает выполнения.

- В домене Admin ввести выбор `DAY`, `MONTH`, `YEAR` и порт чтения
  статистики за заданный UTC-интервал. Вычислять границы от начала текущих
  суток, месяца или года до одного момента формирования отчёта. Сохранить
  IANA-пояс `Asia/Omsk` по умолчанию и возможность выбрать пояс для вызова.
  По одному периоду запрашивать только его. Для сводки запрашивать три
  периода с общей конечной границей. Если начало равно концу, обрабатывать
  пустой по времени период без обращения к API.
- Передавать в результате валюту аккаунта, известную часть суммы как
  `Decimal` и число интервалов без стоимости. Полный нулевой итог требует
  подтверждённого нуля. `null`, неполное покрытие и технический сбой не
  образуют нулевую стоимость. У опубликованного метода `total_cost` отражает
  скидки и считается до списания бонусов. [Описание точки статистики](https://github.com/timeweb-cloud/sdk-go/blob/main/docs/AiKeyTokenStatisticPoint.md).
- Считать 90 суток предельным подтверждённым окном, пока отдельно не
  подтверждено более длинное окно API. Если начало периода за пределами
  окна, вернуть статус «полный период недоступен» без суммы за обрезанный
  период. Это относится и к `YEAR` в сводке. Хранение расширенной истории
  требует отдельного решения. [Ограничение статистики Timeweb](https://timeweb.cloud/docs/ai-gateway/usage-statistics).
- Проверить use case на фиксированных датах Омска и Москвы, в зоне с
  переходом времени, ровно на полуночи и пороге 90 суток. Зафиксировать выбор
  одного или трёх периодов, отсутствие чтения при неизвестном IANA-поясе,
  частичный итог и недоступность одного периода при сохранении остальных.

**Готово, когда** календарные границы, суммы и причины неполноты проверяются
с подменой порта и без изменений действующей маршрутизации.

## 6. Добавить адаптер статистики и настройки Timeweb

**Статус.** Ожидает выполнения.

- Реализовать чтение `GET https://api.timeweb.cloud/api/v1/cloud-ai/ai-keys/statistic/token-usage`.
  Отправлять Bearer-токен аккаунта Timeweb Cloud и параметры `entity_id`
  для UUID выделенного ключа шлюза, `entity_type=aikey`, явные
  `start_time`, `end_time` и `interval`. Использовать все модели этого
  ключа, чтобы учитывать смену модели и резервные модели. Сверить размер
  интервала, выравнивание и границы агрегации на стенде до живой приёмки.
  [Метод GetAiKeyTokenUsageStatistic](https://github.com/timeweb-cloud/sdk-go/blob/main/docs/AIGatewayAPI.md#GetAiKeyTokenUsageStatistic).
- Читать `ai_key_token_statistics` и сверять число точек с `meta.total`.
  Проверять уникальность и границы временных меток и подтверждение покрытия
  запрошенного интервала. Для дробных JSON-чисел использовать `Decimal`
  с момента разбора. Суммировать известные стоимости до округления вывода.
  Отличать явный ноль от `null`, отсутствующего поля и пустой или
  неполной выборки. Число точек с `null` не позволяет определить число
  запросов без цены. [Контракт ответа](https://github.com/timeweb-cloud/sdk-go/blob/main/docs/GetAiKeyTokenUsageStatistic200Response.md).
- Ввести отдельные настройки Admin для токена аккаунта, UUID ключа и
  ISO-кода валюты аккаунта. Для нашей установки использовать `RUB`. Если
  токен и UUID пусты, режим доступен и сообщает, что статистика не настроена.
  Неполный или некорректный набор отклоняет конфигурация включённого Admin.
  Локальная проверка формата и готовности не вызывает внешний API. Для
  доступа использовать токен с правом «просмотр» по проекту ключа и
  проверить доступность работы endpoint с этой ролью на стенде.
  [Токены Timeweb Cloud](https://timeweb.cloud/docs/account-management/token) ·
  [Ограничение прав токена](https://timeweb.cloud/blog/api-tokeny-s-ogranicheniyami-prav-dostupa).
- Использовать таймаут и фиксированный HTTPS-хост без редиректов. Преобразовать
  таймаут, сетевой сбой, HTTP-ошибки и некорректный JSON в безопасную ошибку
  источника. В ответах и логах исключить токен, заголовки, URL запроса и
  тело ошибки. Проверить адаптер fake HTTP на корректном запросе, дробной
  цене, нуле, `null`, дубликатах, несходящемся `meta.total`, неполном
  периоде, `401`, `403`, `404`, `429`, `5xx` и таймауте.

**Готово, когда** адаптер и профиль проходят проверки без настоящего
токена и получают итог только из валидного ответа с проверенным покрытием.
