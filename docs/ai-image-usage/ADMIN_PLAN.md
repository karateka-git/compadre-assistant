# План этапа 5. Режим администрирования и отчёт

Этап открывает доверенным профилям режим `/admin` и выдаёт в личном чате
отчёт `/llm_costs` по общему учёту. Правила команд описаны в
[требованиях](REQUIREMENTS.md#администрирование), а порядок локальных проверок —
в [инструкции запуска](../RUN.md#проверка-изменения-кода).

## 1. Добавить ограничение доступа по профилю приложения

**Статус.** Выполнено в `27b41bb`. Проверены права профиля, скрытие режима, отзыв, кнопки, привязка и разбор списка доверенных ID.

- Расширить общий реестр правилом допуска для отдельной возможности. Ядро
  применяет его к разрешённому `AppUser.id` и личному выбору в каждом событии.
  Публичные возможности сохраняют текущие defaults и поведение. Покрыть вход,
  команду режима, обычный ввод в сохранённом режиме, меню, `/help`, каталог,
  прямые и пошаговые `/enable` и `/disable`, общий контекст кнопок и его
  повторную проверку. Отказ по доверенному доступу не предлагает `/enable`.
- Для `admin` использовать операторский список положительных внутренних ID
  в `ADMIN_TRUSTED_APP_USER_IDS`. Первоначально оператор указывает только
  профиль владельца. При пустом списке доступ закрыт, ошибочный формат
  отклоняется при включённой возможности. При смене списка перезапускаются
  оба процесса каналов. Проверка в новом процессе блокирует сохранённый
  режим после отзыва. Оба привязанных канала используют один `AppUser.id`.
- Определять ID владельца по точной паре из `external_identities.channel`
  и `external_identities.external_user_id` в активной базе через операторскую
  проверку только для чтения. Описать её в шаге 4, включая сверку, что
  привязанные каналы разрешаются в один профиль. Значение по умолчанию для
  ID владельца отсутствует. Username, имя чата и peer ID не дают права.
- Проверить на тестовой возможности, что изменение политики с сохранённым
  режимом блокирует новые команды и старые кнопки. Личное включение и запись
  предпочтения сами по себе недействительны без доверия. После возврата
  доверия учитывается ранее сохранённый личный выбор.

**Готово, когда** общий диспетчер применяет доверенную границу и личный
выбор независимо, а обычные возможности проходят существующие проверки.

## 2. Рассчитать календарные границы отчёта

**Статус.** Выполнено в `b0a8ba7`. Проверены Омск и Москва, смещения при переходе времени, нижние и верхняя границы в SQLite. На Windows проверен источник IANA из `tzdata`.

- В domain новой возможности принимать идентификатор IANA и один момент
  времени UTC. Использовать `Asia/Omsk` для вызова без аргумента. Зона действует
  для текущего вызова. Добавить закреплённую зависимость `tzdata` для окружений
  без системной базы IANA, включая Windows.
- Для сегодня, текущего месяца и года вычислить три локальных полуночи в
  `ZoneInfo` и перевести их в UTC. Передать полуоткрытые интервалы с общей
  верхней границей времени отчёта в один вызов `UsageTotalsReader.read_totals`.
  Вернуть пояс, точные суммы в нанорублях и количество обращений без оценки.
  Чтение выполняется через публичные контракты учёта.
- Проверить границы на фиксированном времени в `Asia/Omsk` и `Europe/Moscow`,
  переход месяца и года вблизи полуночи, зону с переходом времени, значение на
  каждой нижней границе и исключение верхней. Проверить пустую историю,
  неизвестную стоимость и недопустимый пояс. На временной SQLite использовать
  миграции и публичный API учёта для подтверждения точных границ.

**Готово, когда** один снимок даёт три точных агрегата в выбранном поясе
и проверка неизвестного пояса не вызывает чтение.

## 3. Подключить режим и команду в обоих каналах

**Статус.** Выполнено в `1bb0e84`, `f90baec` и `08c457f`. Отчёт прошёл тесты адаптеров обоих каналов на общей SQLite. Проверены отказ в группе до чтения, независимость от Ask, удаление старого пункта меню после отзыва и перезапуска, в том числе после группового события.

- Добавить `/admin` с явным входом без аргументов и зарегистрировать
  `/llm_costs [timezone]` как команду активного режима. Проверять личный чат
  по общему `is_private_chat_address` перед входом и чтением учёта. В группе предложить
  личный чат и исключить из ответа суммы, количество запросов и детали ошибки.
  Команды внутри режима вызываются отдельно от `/admin`.
- Вывести расчётную сумму в рублях за каждый интервал, округлив итог до
  копеек из точного целого без `float`. Отдельно показать число обращений без
  оценки и выбранный пояс. Для ошибки IANA дать пример
  `/llm_costs Europe/Moscow`. Сбой чтения должен дать короткий ответ о
  недоступности отчёта, сохранить режим и зарегистрировать ошибку для
  диагностики.
- Зарегистрировать `admin` в `ENABLED_CAPABILITIES` через существующую
  серверную границу. Загружать список доверенных профилей только при сборке
  `admin` и подключить `create_usage_totals_reader` к общей базе. Сверить
  allowlist, проверку конфигурации, обработчики запуска Telegram и VK и
  сборку без `ask`. Отчёт о накопленной истории доступен с `admin` без
  клиента LLM и его credentials.
- Пройти тесты адаптеров Telegram и VK на общей временной базе. Проверить
  владельца в обоих привязанных профилях, другого и незарегистрированного
  пользователя, вызов вне режима и из группы, независимость режимов чатов,
  прямой ввод и кнопки, отзыв права в сохранённом режиме. Для отказов
  убедиться, что агрегаты не читаются. Проверить команды и меню после
  отзыва, неправильный аргумент и пустой отчёт.

**Готово, когда** доверенный профиль в активном `/admin` получает отчёт
в исходном личном чате Telegram или VK, а недопущенные вызовы завершаются
до чтения агрегатов.
