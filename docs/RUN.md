# Запуск и проверка проекта

Для первого запуска сначала выполните [SETUP.md](SETUP.md): получите код,
создайте и заполните `.env`. Здесь описан запуск уже подготовленного проекта.

| Задача | Где начать |
| --- | --- |
| Проверить изменение кода | [Проверка изменения кода](#проверка-изменения-кода) и [карта кода](CODE_MAP.md). |
| Обычный локальный запуск и быстрые проверки | [Скрипты `open-*.cmd`](#быстрый-запуск-через-скрипты). |
| Прямой запуск Docker и диагностика по шагам | [Подробный запуск и проверки](#подробный-запуск-и-проверки). |
| Подключение vault и пользовательские команды | [Регистрация и подключение Obsidian](#12-зарегистрироваться-и-подключить-obsidian-vault). |
| Индексы и embeddings | [Настройки document chunker](#настройки-document-chunker) и [embeddings](#настройки-embeddings). |

`healthcheck` проверяет локальную конфигурацию и SQLite без внешних API;
автономные smoke работают с временной БД. Живой сценарий с ботом, GitHub и LLM
проверяется отдельно — успешный healthcheck его не подтверждает.

## Проверка изменения кода

Сначала найдите связанные тесты в [карте кода](CODE_MAP.md). Для одного файла
тестов из корня проекта:

```powershell
python -m unittest discover -s tests -p 'test_chat_modes.py'
```

Для полного набора unit-тестов:

```powershell
python -m unittest discover -s tests
```

Локальный запуск отдельного файла не заменяет проверку PR или допуск релиза.
Состав `pr-check` находится в [workflow PR](../.github/workflows/pr-fast.yml),
а полный набор и дополнительные проверки — в
[check-full-suite](../.github/workflows/full-suite.yml). Условия выпуска описаны в
[RELEASES.md](RELEASES.md).

### Проверить ссылки Markdown

Запустите команду из корня рабочей копии.

```powershell
python -X utf8 -m scripts.check_markdown_links
```

Команда проверяет все Markdown-файлы, которые Git отслеживает в текущей
рабочей копии. Добавьте новые документы и файлы, на которые они ссылаются,
в индекс перед проверкой. [Скрипт](../scripts/check_markdown_links.py) сверяет
однострочные внутренние ссылки и ссылки на изображения с путями в репозитории,
а якоря Markdown — с заголовками ATX и Setext. Он работает без сетевых запросов.
Для ошибки откройте указанные файл и строку, исправьте ссылку или её цель и
запустите команду снова. Успешный результат показывает ноль ошибок.

## Быстрый запуск через скрипты

Скрипты `open-*.cmd` открывают отдельное окно PowerShell, выполняют нужные команды и оставляют окно открытым после завершения. Скрипты проверок и запуска команд внутри контейнера сначала пересобирают образ `compadre-assistant:dev`, чтобы Docker использовал свежий код проекта.

Запустить сборку и старт каналов из `ENABLED_CHANNELS` (по умолчанию Telegram и VK):

```powershell
.\scripts\open-dev-start.cmd
```

Для одного канала задайте в `.env` `ENABLED_CHANNELS=telegram` или
`ENABLED_CHANNELS=vk`. Scripts читают итоговую конфигурацию Compose, запускают
выбранные сервисы и останавливают ранее запущенный невыбранный сервис.
`check-health` и `check-all` проверяют все выбранные каналы. Проверки прерываются
при первом ненулевом коде команды Docker. Имена `open-*.cmd` и debug-режим сохранены.

Запустить проект с debug-логами только для текущего окна:

```powershell
.\scripts\open-dev-start.cmd debug
```

Проверить все текущие smoke-сценарии:

```powershell
.\scripts\open-check-all.cmd
```

Минимальный operational checklist для ежедневного запуска описан в
[OPERATIONS.md](OPERATIONS.md).

Проверить реальную ссылку:

```powershell
.\scripts\open-process-url.cmd "https://habr.com/ru/articles/198682/"
```

Обработка обычной статьи в Telegram после регистрации, сохранения имени и
подключения vault (при отсутствии ожидающего подтверждения):

- сообщение без ссылки получает просьбу прислать ссылку и не сохраняется в `incoming_messages`;
- сообщение с HTTP/HTTPS-ссылкой сохраняется в `incoming_messages`;
- после успешной обработки URL сохранённое сообщение связывается со статьёй через `incoming_messages.article_id`;
- после извлечения текста статья анализируется через OpenAI-compatible LLM, результат сохраняется в `analysis_results` и возвращается пользователю Markdown-сводкой;
- повторная ссылка переиспользует сохранённую статью и последний сохранённый анализ;
- если обработка ссылки завершилась ошибкой, диагностическая запись связывается с сообщением через `processing_errors.incoming_message_id`;
- если анализ завершился ошибкой, диагностическая запись также связывается с сообщением через `processing_errors.incoming_message_id`;
- повтор того же Telegram message id не создаёт дубль сообщения.
- ошибки загрузки, извлечения и анализа получают разные пользовательские ответы;
- диагностические ошибки можно смотреть в `processing_errors`.

Если отдельное окно не нужно, можно запускать `.ps1`-версии в текущей консоли:

```powershell
.\scripts\check-all.ps1
```

## Запуск через Codex

При этих фразах Codex выполняет команду из корня проекта. По умолчанию
`open-*.cmd` открывает отдельное окно PowerShell и оставляет его открытым:

| Фраза пользователя | Команда |
| --- | --- |
| `запусти проект` | `.\scripts\open-dev-start.cmd` |
| `запусти проект в дебаг` | `.\scripts\open-dev-start.cmd debug` |
| `проверь healthcheck` | `.\scripts\open-check-health.cmd` |
| `проверь pipeline` | `.\scripts\open-check-pipeline.cmd` |
| `проверь всё` | `.\scripts\open-check-all.cmd` |
| `проверь ссылку <URL>` | `.\scripts\open-process-url.cmd "<URL>"` |

Для `проверь ссылку` без URL использовать
`https://habr.com/ru/articles/198682/`. Режим `debug` выставляет
`APP_DEBUG=true` только для этого запуска. Если пользователь явно просит
проверку без отдельного окна, выполнить соответствующий `.ps1`-скрипт в
текущей Codex-консоли: `check-health.ps1`, `check-pipeline.ps1`,
`check-all.ps1` или `process-url.ps1` с URL.

## Debug-логи

Если нужно видеть больше деталей в консоли сервера, включить в `.env`:

```dotenv
APP_DEBUG=true
```

После перезапуска проекта в логах появятся безопасные debug-события incoming-flow:
регистрация/привязка пользователя, сохранение входящего сообщения, ID статьи,
ID анализа и итоговый тип результата. Секреты и длинные тексты не выводятся.

## Подробный запуск и проверки

### 1. Перейти в папку проекта

```powershell
cd <путь-к-клонированному-репозиторию>
```

Замените `<путь-к-клонированному-репозиторию>` своим путём. Все следующие команды
выполняются из этой папки.

### Пересоздание базы после изменения схемы

Для проверки миграций на отдельной тестовой БД доступен явный CLI-вызов
`python -m compadre_assistant --migrate --database-path <путь-к-БД>`.
Явный путь не требует `.env` и секретов ботов. Без `--database-path`
команда читает `DATABASE_PATH` из окружения или локального `.env`.
Выполнять её на рабочей production-БД
разрешается только внутри согласованного порядка выпуска:
контроллер сначала останавливает оба writer и делает проверенную копию.
Полный CI проверяет применение схемы к свежей и предыдущей тестовой БД;
он не изменяет production SQLite. Правила и ограничения возврата описаны
в [OPERATIONS.md](OPERATIONS.md#отказ-выпуска-и-возврат).

Production уже применил `0001_initial_schema.sql`; менять этот файл
нельзя. `0002_user_capability_preferences.sql` добавляет личные настройки
без удаления профилей, статей или режимов. `0003_backfill_existing_user_names.sql`
заполняет имя «Анатолий» только существующим профилям с `display_name = NULL`.
`0004_private_chat_address_lookup.sql` добавляет индекс адреса личного чата
для точечной проверки владельца; сохранённые записи не изменяет.
`0005_ask_usage.sql` добавляет пустую таблицу метаданных вызовов ИИ без
привязки к пользователям. Данные существующих таблиц сохраняются.
Таблица `ask_usage` и её записи сохраняются для совместимости с ранее
выпущенными версиями. Отчёт о расходах получает статистику из Timeweb.
`0006_ai_capability_id.sql` переименовывает `ask` в `ai` в сохранённых
режимах и личных настройках. Владельцы, состояния доступа и ревизии
сохраняются. При конфликте двух ID одного профиля транзакция откатывается.
Следующие изменения схемы оформляются последовательными миграциями с
сохранением данных. Даже на локальной
development-БД пересоздание не заменяет миграцию будущего выпуска.

Перед новым запуском после изменения схемы остановить контейнеры и другие
процессы, использующие БД. Удалить `data/app.db` и оставшиеся файлы
`data/app.db-wal` / `data/app.db-shm`, затем запустить приложение снова.
При старте оно создаст новую базу и последовательно применит миграции.
Каталог `data/` целиком не удалять: в нём хранится также PEM GitHub App.

Этот порядок относится только к локальной development-БД. Production SQLite
нельзя удалять по этому разрешению; см. [PRODUCTION.md](PRODUCTION.md).
После завершения этапа разработки
пересоздание с потерей данных больше не допускается на основании текущего
разрешения: изменения схемы выполняются миграциями с сохранением данных,
а удаление БД требует отдельного явного разрешения пользователя.

Это согласованный порядок разработки: сохранение промежуточных данных,
перенос и резервная копия перед таким пересозданием не требуются, отдельное
подтверждение не нужно. Изменение обычных записей или кода без изменения схемы
не требует очистки. Скрипты запуска автоматически схему не сравнивают и БД
не удаляют; пересоздание выполняется перед запуском.

Новая база не содержит технических пользователей. Первый успешный `/register`
создаёт `app_user_id=1`.

Удаление `data/app.db` полностью удаляет локальные данные разработки, включая
пользователей, привязки Telegram/VK, статьи, анализы и данные Obsidian vault.

Ранее созданная БД не обновляется повторным применением `0001`: runner
применяет ещё не выполненные миграции. Для действующей
development-БД пересоздание не требуется; проверьте применение ожидающих
миграций командой `--migrate` выше. Автономные проверки
работают с временными БД и не требуют очистки рабочей базы.
В шаге 2.2 схема не менялась. `/obsidian` выбирает режим конкретного чата,
`/exit` очищает только его маршрут. После выхода обычный текст и URL предлагают
вход, не запуская обработку статьи. Сохранение имени завершает регистрацию
профиля; GitHub/vault подключается отдельно внутри Obsidian. В шаге 2.5 схема
не менялась, пересоздание БД из-за одной конфигурации не требуется.

### 2. Запустить Docker Desktop

```powershell
docker desktop start
```

Команда запускает Docker Desktop и Docker Engine.

### 3. Проверить готовность Docker

```powershell
docker info
```

Команда должна вывести информацию о `Client` и `Server`. Если раздел `Server` ещё недоступен, нужно немного подождать и повторить команду.

### 4. Собрать и запустить проект

```powershell
docker compose up --build
```

Команда собирает или обновляет образ, создаёт контейнер и запускает Telegram-бота и VK-бота в polling-режиме. Окно нужно оставить открытым, пока бот должен принимать сообщения.

Если настроен только один канал, укажите сервис: `docker compose up --build
tg_assistant` или `docker compose up --build vk_assistant`. Отсутствие токена не
отключает второй сервис автоматически. Используйте scripts с `ENABLED_CHANNELS`
для выбора сервисов. `--telegram-bot` проверяет только Telegram, `--vk-bot` —
только VK; токен другого канала не требуется.

В выводе команды сначала показывается сборка образа:

- строки с `#1`, `#2` и другими номерами шагов выполняет Docker;
- `[internal]` означает внутренние действия сборщика;
- установка пакетов через `pip` относится к зависимостям из `requirements.txt`;
- `CACHED` означает, что готовый слой взят из кэша и не выполнялся заново.

Затем Docker Compose подготавливает и запускает контейнер:

```text
Image compadre-assistant:dev Built
Network ... Created
Container ... Created
Attaching to tg_assistant-1, vk_assistant-1
```

Строки с префиксом `tg_assistant-1 |` / `vk_assistant-1 |` и именем `compadre_assistant` выводит уже наше Python-приложение:

```text
tg_assistant-1 | ... INFO compadre_assistant: Starting Compadre Assistant 0.1.0
tg_assistant-1 | ... INFO compadre_assistant: Telegram bot polling started
```

Остановить бота можно через `Ctrl+C` в окне, где запущен `docker compose up`.

Для повторного запуска уже собранного образа без проверки пересборки используется:

```powershell
docker compose up
```

Эта команда запускает существующий образ. После изменения `Dockerfile`, `requirements.txt` или кода проекта нужно снова использовать `docker compose up --build`, чтобы изменения попали в образ.

### 5. Проверить результат запуска

```powershell
docker compose ps -a
```

Команда показывает контейнер проекта. Статус `Exited (0)` означает, что приложение завершилось без ошибки.
Для запущенного бота ожидается статус `Up`.

### 6. Выполнить healthcheck

```powershell
docker compose run --rm tg_assistant python -m compadre_assistant --healthcheck --channels telegram
docker compose run --rm vk_assistant python -m compadre_assistant --healthcheck --channels vk
```

Команда проверяет выбранный канал, включённые возможности, доступность папки
`data/` для записи и подключение SQLite. Без `--channels` выбирается список
`ENABLED_CHANNELS` (по умолчанию `telegram,vk`). После проверки временный контейнер удаляется.

Healthcheck не вызывает API Telegram, VK, GitHub или LLM: он проверяет формат
Telegram token или наличие VK token/положительного group ID, настройки включённых
LLM/embeddings и возможность подписать JWT локальным PEM. URL проверяется
локально. Все независимые результаты выводятся отдельно; пользовательский vault
не проверяется. Пустые GitHub/LLM-группы отмечаются как недоступные функции,
пустые embeddings — как FTS fallback; общие команды остаются готовы и результат
может быть успешным. Частичная/невалидная группа включённой возможности даёт
ненулевой код, даже если обычные команды профиля могли бы работать.
Живой polling, права GitHub и доступность моделей этой командой не проверяются.
Она открывает рабочую БД (может создать пустой файл), но не применяет миграции
и не проверяет актуальность схемы. Статус `healthy` не подтверждает полный
пользовательский сценарий.

### 7. Проверить SQLite-контур

```powershell
docker compose run --rm tg_assistant python -m compadre_assistant --sqlite-smoke
```

Команда создаёт временную базу, применяет миграции, повторно проверяет их идемпотентность, записывает тестовую статью через `ArticleRepository` и читает её обратно. Рабочая база `data/app.db` не изменяется.

### 8. Проверить обработку URL

```powershell
docker compose run --rm tg_assistant python -m compadre_assistant --process-url "https://example.com/article"
```

Команда запускает текущий article pipeline: нормализует URL, создаёт или переиспользует статью в SQLite, загружает HTML, извлекает чистый текст и сохраняет результат в `data/app.db`.

Это только загрузка и извлечение текста, без LLM, поиска и GitHub write-back.
Команда требует только `APP_ENV` и `DATABASE_PATH`; не читает настройки каналов
или провайдеров возможностей. Smoke-команды вообще не загружают `.env`.
Текущий CLI использует `app_user_id=1` и не создаёт пользователя: в выбранной
БД он уже должен существовать (первый `/register` в новой базе создаёт ID 1).
На пустой БД запись статьи завершится ошибкой внешнего ключа. Команда работает
с данными этого пользователя; для проверки без рабочей БД используйте
`--pipeline-smoke`.

### 9. Проверить pipeline без интернета

```powershell
docker compose run --rm tg_assistant python -m compadre_assistant --pipeline-smoke
```

Команда создаёт временную базу, применяет миграции и проверяет article pipeline на fake HTML-загрузчике и fake extractor. Рабочая база `data/app.db` не изменяется.

### 10. Проверить анализ без LLM

```powershell
docker compose run --rm tg_assistant python -m compadre_assistant --analysis-smoke
```

Команда создаёт временную базу, применяет миграции, создаёт статью с извлечённым текстом и проверяет analysis pipeline на fake LLM-анализаторе. Рабочая база `data/app.db` не изменяется.

### 11. Проверить VK adapter отдельно

Для VK нужны настройки в `.env`:

```dotenv
VK_BOT_TOKEN=...
VK_GROUP_ID=...
```

При обычном запуске `docker compose up --build` VK long polling стартует
вместе с Telegram. Отдельная команда ниже нужна для изолированной проверки VK:

```powershell
docker compose run --rm --entrypoint python vk_assistant -m compadre_assistant --vk-bot
```

VK adapter использует тот же incoming-flow, регистрацию, привязку каналов,
сохранение статей и LLM-анализ, что и Telegram.

### 12. Зарегистрироваться и подключить Obsidian vault

После запуска ботов выполните регистрацию, подготовку правил и подключение
GitHub App по [GITHUB_APP.md](GITHUB_APP.md). Для проверки пользовательского
сценария отправьте ссылку на статью в режиме Obsidian: ожидаются анализ,
предложение изменения и запрос подтверждения. Ответ `нет` оставляет vault
без изменений; `да` записывает только `add`/`update`, а `skip`
завершается без commit. Повторная ссылка использует сохранённый результат;
`/reanalyze <article_id>` заново загружает источник.

### 13. Посмотреть доступные команды

Нажмите «Помощь» в Telegram или VK. Ручной ввод `/help` открывает ту же
справку. После её просмотра можно продолжить с прежней страницы, прислать
ожидаемое значение в исходный срок или нажать кнопку исходного решения.

Справка зависит от состояния этого диалога. До регистрации она предлагает
`/register`, в личном диалоге также `/link`. Во время ввода имени она показывает
шаг завершения регистрации и `/cancel`. После регистрации справка с главной
перечисляет доступные входы `/ai`, `/obsidian`, `/settings` и `/family`
(«Семья» доступна только в личном чате).
Доверенный профиль в личном чате
также видит `/admin`. На главную можно вернуться кнопкой выхода из режима.
В режиме Obsidian появляются команды хранилища,
после `/exit` возвращается основной список. При другом ожидании значения
`/help` добавляет описание ожидаемого шага и `/cancel`. Актуальные
подтверждения показаны отдельно; при недоступности источника список явно
помечен неполным. Текст строится из публичного каталога команд и проверенных
снимков чата. Формулировки и условия ответов смотрите в
[правилах сообщений](USER_MESSAGES.md) и реестрах
[ядра](user-messages/CORE.md), [ИИ](user-messages/AI.md),
[Admin](user-messages/ADMIN.md), [Obsidian](user-messages/OBSIDIAN.md) и
[«Семьи»](user-messages/FAMILY.md).

В системном меню команд Telegram доступна только `/help`. В личном диалоге VK действия текущего раздела показаны
нижней клавиатурой возле поля ввода. Их состав и подписи задаёт владелец экрана.
Команды с поддерживаемым пошаговым вводом без аргумента запрашивают значение
следующим сообщением. Ожидание действует десять минут в исходном чате;
неверное значение не продлевает срок. `/cancel` снимает его, не меняя режим.
Временный выбор может появиться кнопкой под конкретным ответом.
Постоянная клавиатура VK остаётся для команд; временный выбор не дублируется
в ней. Если кнопка устарела, откройте актуальный экран по предложенному
действию. Применимые ручные команды можно посмотреть в «Помощи».

Общие команды находятся в [commands.py](../compadre_assistant/core/presentation/incoming/commands.py),
точки входа регистрирует [registry.py](../compadre_assistant/core/presentation/incoming/registry.py).
Откройте `/settings`, чтобы посмотреть профиль через `/status` или изменить
имя через `/name <name>`. Чтобы вернуться на главную, отправьте `/exit`.
В настройках `/capabilities` показывает названия возможностей, их ID,
личный выбор и доступность на сервере. Без явной строки настроек выбрана
возможность ИИ и «Семья», Obsidian выключен, а Admin выбран только для
допущенного профиля. Для работы с Obsidian
при его серверной доступности отправьте `/enable obsidian`, затем `/obsidian`.
`/disable ai` отключает доступ к режиму ИИ. `/enable ai` восстанавливает
доступ к входу `/ai` и сохранённому режиму. В пошаговом выборе через
`/enable` и `/disable` выбирай «Режим ИИ».
Команды изменения требуют точный ID из `/capabilities`, меняют один личный
выбор и действуют во всех привязанных Telegram/VK каналах одного профиля.
Повтор команды сообщает, что возможность уже включена или выключена. Если
ID неизвестен, профиль не зарегистрирован, сервер не предоставляет вход либо
запись SQLite не удалась, бот сообщает отказ без успешного подтверждения.
`/obsidian [текст или URL]` включает работу с vault и обрабатывает аргумент.
Без аргумента вход объясняет действия и при необходимости предлагает подключить
vault; после входа доступны внутренние команды. Голая ссылка вне режима
показывает доступные входы. Обработка статьи или подключение GitHub начинаются в разделе «Статьи в Obsidian».
Управление vault: `/vault_status`, `/vault_sync`, `/vault_disconnect`;
повторная обработка: `/reanalyze <article_id>`.

`ENABLED_CAPABILITIES=obsidian` разрешает этот вход на сервере, но личное
`/enable obsidian` требуется в настройках. При пустом значении после перезапуска
остаётся вход `/settings`, доступный каждому зарегистрированному профилю.
`/enable` действует в пределах серверного
списка и прав профиля. Общая справка показывает доступные входы, их команды и
`/exit` для длительных режимов. Сохранённый ID отключённой возможности
остаётся в SQLite: следующий текст, прямая команда и предметный `/confirm`
не запускают её handler. При личном отключении бот предлагает открыть
`/settings` и включить возможность. При серверном отключении её состояние
можно посмотреть через `/capabilities` в настройках.
`/disable` не удаляет режим и предметные данные; после `/enable` сохранённый
режим снова доступен. `/exit` отдельно очищает только режим текущего чата.
Запросы ИИ и Device Flow, начатые до отключения возможностей, завершаются
с ответом в исходный чат.
Настройки профиля работают при отключённом Obsidian. Вход различает
отключённую возможность, ненастроенный GitHub/LLM-провайдер и неподключённый
vault пользователя. Конфигурация и healthcheck разделены:
отключённые группы не проверяются; отсутствующий провайдер и неподключённый
vault диагностируются отдельно. Невалидные включённые группы блокируют startup.

Для одного профиля в Telegram и VK откройте `/settings` в уже подключённом
личном чате и выберите «Мессенджеры» или отправьте `/connect`.
В Telegram выполните `/connect vk`, в VK — `/connect telegram`.
Свободный мессенджер получает код на десять минут. Затем отправьте `/link <code>` в личном
чате второго канала. Если у второго канала уже есть профиль, сначала откройте
там `/settings`. Если этот канал принадлежит другому профилю, бот запросит
подтверждение переноса связи.

В обоих процессах список мессенджеров берётся из `ENABLED_CHANNELS`.
Публичный диалог Telegram строится из `TELEGRAM_BOT_USERNAME`, например
`example_chat_bot`: это имя бота именно этой установки из BotFather, а не
адрес произвольного Telegram-бота. Задайте его в окружении обоих процессов,
включая VK, который показывает ссылку на Telegram. Имя не извлекается из токена.
При создании контейнера Compose передаёт ожидаемое публичное имя в его
healthcheck. Оба сервиса проверяют ссылку из настроек приложения без обращения
к Telegram. Если установка работает только в VK, оставьте имя Telegram пустым.
Диалог VK строится из `VK_GROUP_ID`
[в формате ссылки на сообщения сообщества](https://object2-ac.vk-apps.com/vk-education-0554ff56-27eb-4093-a702-685722cef6d9/media/91/6b9101abe2f54a788fedfc39f9b04fb8.pdf).
При отсутствии адреса сохраняется переход вручную в знакомый диалог.
Для уже связанного мессенджера раздел показывает статус и настроенную ссылку.

Подтвердите перенос в исходном личном чате. Перенесённый канал получает выбор
и доступ профиля назначения. Статьи, vault, личные настройки и членство в
семье принадлежат своим профилям. Если переносится последний канал профиля,
который состоит в семье, сначала завершите его членство.

#### Ожидающие действия и исходный чат

Разные статьи одного профиля из Telegram/VK имеют отдельные proposals.
Повтор нормализованного URL использует ту же статью и её активное предложение,
не создавая конкурирующий review. Повтор этой статьи из другого чата получает
указание завершить действие в исходном чате без preview чужого предложения.
Обычные новые ссылки и команды профиля чужим ожиданием не блокируются.

При нескольких локальных ожиданиях выбирайте команду из нужного ответа:

```text
/confirm obsidian proposal <id> <version> yes
/confirm obsidian proposal <id> <version> no
```

После `/exit` сначала войдите через `/obsidian` в том же исходном чате.
Старая команда с уже завершённым ID или изменившейся версией не применяет новое
предложение. Sync/write-back одного vault идут под общим SQLite lease; занятость
сохраняет ожидание, а расхождение SHA требует пересчёта с новым подтверждением.
`/reanalyze <article_id>` также требует завершить активное действие этой статьи.

Если `/link` предлагает перенос уже привязанной identity, используйте возвращённые
команды `/confirm core identity <id> <version> yes|no`. Они доступны независимо
от режима. Обычные `да`/`нет` в Obsidian не подтверждают перенос профиля.

При несовместимом изменении схемы отдельную development-БД пересоздают по
[правилам проекта](../AGENTS.md) и [порядку выше](#пересоздание-базы-после-изменения-схемы).
Автономные проверки используют временные БД.

## Учитывать семейные расходы

В личном Telegram или VK откройте `/family` и нажмите «Расходы». Для входа нужен профиль с доступом к «Семье» и действующее членство. Создание семьи и вступление по приглашению описаны в [следующем разделе](#вести-семейный-список-покупок).

1. Выберите «Добавить расход». Отправьте одно фото чека или напишите, например, «Такси 450». Можно также выбрать «Ввести пошагово» и указать название, сумму и категорию. Пошаговый ввод доступен и при сбое распознавания.
2. Проверьте дату, категории и итог в рублях. Если сумма позиций расходится с итогом, на экране появится строка «Без детализации» с разницей. «Исправить» позволяет изменить покупку. «Сохранить» запишет показанный итог. На подтверждение есть десять минут с показа текущей редакции.
3. В сводке выберите период. Нажмите «По категориям», выберите товар и затем покупку, чтобы увидеть весь чек. Кнопка «Найти товар» ищет по части названия внутри выбранного месяца. «Диаграмма» отправляет изображение с суммами категорий, «Назад» возвращает в сводку.
4. При необходимости нажмите «Часовой пояс» → «Изменить пояс» и введите зону IANA. Изменение действует для всей семьи. Исходный пояс — `Asia/Omsk`.

Распознавание фото и свободного текста использует конфигурацию `ASK_*`. Для фото нужна модель с поддержкой изображений. [Настройка модели](SETUP.md) · [Экраны расходов](user-messages/FAMILY.md#внести-семейный-расход).

## Вести семейный список покупок

В личном чате Telegram или VK зарегистрируйтесь через `/register` и
отправьте `/family`. Если команда недоступна, проверьте `family` через
`/settings` → `/capabilities`. [Настройка сервера](SETUP.md#включить-семью).

1. Для новой семьи выберите «Создать семью» или отправьте `/family_create`,
   затем пришлите название. Если вас пригласили, выберите «Вступить по коду»
   или отправьте `/family_join`, затем пришлите код. После успешного ввода
   откроется меню с названием семьи.
2. Чтобы пригласить ещё одного человека, откройте «Пригласить», выберите
   «Создать код» или отправьте `/family_invite create`. Передайте код тому,
   кто должен вступить. Он действует 24 часа с момента выдачи и погашается
   при первом успешном вступлении.
3. Откройте «Покупки» или отправьте `/family_shopping`. Нажмите «Добавить»
   или отправьте `/add`, затем пришлите товары по одной покупке на строку.
   Название и количество записываются одной строкой. Можно добавить покупку
   сразу через `/add Молоко, 2 л`. Чтобы исправить запись в «Нужно купить»,
   удалите её и добавьте заново. Для отмены ввода нажмите «Отмена» или
   отправьте `/cancel`, затем откройте `/family_shopping`.
4. Нажмите «Купить» или «Удалить» либо отправьте `/buy` или `/delete` без
   аргументов. В ответе из группы «Нужно купить» нажмите товар или пришлите
   его видимый номер отдельным сообщением, например `2`. После каждого
   выбора бот обновит сообщение выбора. В обычном списке страница показывает
   до десяти товаров «Нужно купить». Группа «Куплено» целиком отображается
   на последней странице, имеет свою нумерацию и очищается действием
   «Очистить купленное» или командой `/family_clear_bought`.
5. В Telegram действия доступны под списком, а справка о ручных командах
   открывается через `/help` в меню `/`. В VK действия обычного списка
   доступны на клавиатуре рядом с полем ввода. Откройте «Помощь» в меню
   семьи или отправьте `/help` из покупок, чтобы прочитать о командах.
   При выборе товаров VK открывает отдельное сообщение с кнопками и сохраняет
   нижнее меню. «Назад» из выбора возвращает к странице обычного списка,
   с которой вы открыли выбор. Из обычного списка можно вернуться к
   карточке семьи. Если кнопка или редактирование недоступны, откройте
   актуальный список через `/family_shopping` или карточку через `/family`.
6. Для работы из второго канала [свяжите чаты с одним профилем](#13-посмотреть-доступные-команды),
   затем откройте `/family` и «Покупки» в этом чате. При следующем открытии
   списка любой участник увидит изменения, сделанные из другого канала.

Когда другой участник добавляет товары, бот присылает сводку в ваш личный
чат. Она готова через две минуты тишины или через десять минут после первого
добавления, если список продолжают пополнять. Например, два добавления
в 18:00 и 18:01 дают одну сводку в 18:03. В ней видны до пяти товаров и
количество остальных. Уже купленные и удалённые позиции пропускаются.
При пустой подборке сообщения не будет.

При регистрации уведомления включаются в том мессенджере, где вы создали
профиль. Чтобы перенести их, откройте «Настройки» → «Мессенджеры» и выберите
другой связанный канал. Если у старого профиля связаны оба канала и выбор
ещё пуст, укажите один здесь. Ожидающие сводки придут в выбранный чат,
если покупки ещё актуальны.

Получение сводки сохраняет текущий режим. Нажмите «Открыть покупки», чтобы
перейти к актуальному списку. После выхода из семьи или нового вступления
старое сообщение уже не открывает покупки.

Чтобы управлять участниками, откройте «Участники» или отправьте
`/family_members`. Владелец выбирает другого участника для исключения или
передачи роли. Единственный владелец может закрыть семью и удалить список.
Обычный участник может выйти сам. Подтвердите действие кнопкой или получите
адресную команду через `/confirm` в том же чате. Подтверждение действует
десять минут. Повторный `/family` возвращает
на главную режима, `/exit` закрывает режим только в текущем чате.
[Команды, ответы и отказы](user-messages/FAMILY.md).

Для локальной проверки используйте [отдельную development-БД](#пересоздание-базы-после-изменения-схемы).
Автоматические сценарии используют временные БД и подмены каналов.
Доставку и внешний вид в Telegram и VK проверяют отдельно в личных чатах.

## Задать вопрос в режиме ИИ

После завершения `/register` с вводом имени отправьте `/ai` в нужном чате
Telegram или VK. Вход доступен, если `ai` включён в `ENABLED_CAPABILITIES`
и лично не отключён. В активном режиме отправьте `/ask <question>`.
`/ask` без аргумента ожидает вопрос следующим сообщением в том же чате.
Во время ожидания «Отмена» в нижнем меню VK и ручная команда `/cancel`
прекращают ожидание. `/exit` завершает режим.
При доступной фоновой доставке приём допустимого вопроса подтверждается
сообщением «Вопрос принят. Готовлю ответ… Для отмены введи /cancel.». Во время
работы `/cancel` сразу освобождает чат и отменяет
доставку ответа. Уже начатый запрос к модели учитывается. Результат приходит
целиком или несколькими сообщениями через обычное разбиение длинных ответов канала.
Streaming не используется.

Каждый вызов содержит только текущий вопрос и постоянную инструкцию. Истории,
памяти и чтения URL/vault нет. `/ask` с URL рассматривает ссылку как текст.
Для работы достаточно профиля ИИ. Режим ИИ сохраняется после ответа.
Ожидающие подтверждения Obsidian остаются доступны после возвращения
в их исходный чат и режим. Обычный текст без ожидания и неизвестные команды
в режиме ИИ получают подсказку `/ask`.

Пустой или слишком длинный вопрос получает подсказку без вызова API. При timeout,
ошибке провайдера, пустом/некорректном или превышающем лимит ответе бот предлагает
повторить вопрос позже. Автоматические повторы API отключены. Ключи, тело ответа
провайдера и детали исключений пользователю не показываются.

Профиль и варианты включения ИИ описаны в [SETUP](SETUP.md#настройка-ии).
Для проверки конфигурации используйте обычный healthcheck. Реальный запрос
проверяйте отдельно в выбранном чате. Отправьте `/ai`, затем
`/ask Ответь одним словом: готово`.
Автономные тесты и smoke не выполняют такую внешнюю проверку.

## Получить текст с фото в режиме ИИ

1. Войдите в `/ai` в нужном чате Telegram или VK. Отправьте
   `/get_text_from_image` либо нажмите «Извлечь текст с фото».
2. В течение 10 минут отправьте одно фото или скриншот как фотографию JPEG
   или PNG размером до 10 МиБ. `/cancel` отменяет ожидание, а `/exit` завершает
   режим до приёма фото. Фото можно отправить без подписи. После приёма бот
   сразу сообщает «Фото получено. Распознаю текст. Для отмены введи /cancel.».
   Во время ожидания и обработки в системном меню Telegram проверьте `/help`,
   а в нижнем меню VK — «Отмена».
3. Проверьте, что результат пришёл в исходный чат и сохранил порядок и переносы
   строк. Неразборчивые места обозначаются `[неразборчиво]`. При отсутствии
   текста бот сообщает об этом отдельно. Для нового фото или повторной попытки
   вызовите `/get_text_from_image` ещё раз.

Для эксплуатационной проверки повторите шаги с синтетическим изображением с
известным многострочным текстом в каждом канале. Проверьте квитанцию, результат,
отмену до и после приёма и фото без ожидания. Пока распознавание идёт, команды
и кнопки в этом чате получают подсказку, а `/cancel` сразу освобождает чат.
После отмены распознанный текст не приходит. Автономный тест проверяет порядок
квитанции и сетевой работы, отмену при заблокированной сети и запись уже
начатых запросов в общей временной SQLite. После результата, ошибки или отмены
проверьте, что меню вернулось к текущему режиму. Доставку, меню и актуальные
хосты CDN проверяйте в живых клиентах каналов.

## Посмотреть расходы ИИ

В личном диалоге Telegram или VK отправьте `/admin`. Режим появляется в меню
у допущенных профилей. Чтобы восстановить личный доступ при действующем
праве, откройте `/settings` в личном чате и отправьте `/enable admin`.
[Настройка доверенного доступа](SETUP.md#настроить-режим-администрирования).

В активном режиме нажмите «Показать расходы ИИ». Сводка показывает текущие
сутки, месяц и год в `Asia/Omsk`. Кнопки «Сегодня», «Текущий месяц» и
«Текущий год» выбирают отдельный период, «Сводка» возвращает все три.
«Часовой пояс» запрашивает название IANA обычным сообщением, например
`Europe/Moscow`; выбранный период сохраняется. Неверный ввод можно повторить
до исходного срока 10 минут. «Отмена» сохраняет прежний пояс, «Помощь» открывает
справку текущего шага. Выбор относится только к текущему чату и входу в режим.

Ручные команды остаются доступны в справке: `/llm_costs DAY`,
`/llm_costs Europe/Moscow`, `/llm_costs MONTH Europe/Moscow`.
`/llm_timezone` открывает ввод пояса, `/llm_timezone Europe/Moscow` меняет
его сразу для выбранного периода. Прямой вызов отчёта без пояса использует
`Asia/Omsk`. «Выйти из режима» или `/exit` завершает режим текущего чата.

В отчёт входит статистика всех моделей выделенного ключа Timeweb AI Gateway.
Строка показывает число запросов, если Timeweb подтвердил весь её период.
При недоступности счётчика известная сумма сопровождается текстом «Число
запросов недоступно.» Отчёт показывает доступное число и при сбое чтения суммы.
Суммы в валюте аккаунта учитывают скидки и отражают стоимость до списания
бонусов. Если у части интервалов отсутствует оценка, отчёт помечает известную
сумму и число интервалов без стоимости. Если полного периода в 90-дневном
окне нет, например для года в ноябре, отчёт отдельно указывает это.
[Настройка и диагностика](OPERATIONS.md#обновить-настройки-отчёта-timeweb).

## Настройки document chunker

Независимый Markdown/Obsidian chunker использует технические размеры из
необязательных переменных `.env`:

```dotenv
CHUNK_MINIMUM_SIZE_CHARS=300
CHUNK_TARGET_SIZE_CHARS=3000
CHUNK_MAXIMUM_SIZE_CHARS=6000
```

Если переменные отсутствуют, используются эти же значения по умолчанию.
`minimum` и `target` являются мягкими ориентирами, а `maximum` — жёстким лимитом
для обычного делимого текста. Эти параметры не относятся к содержательным
правилам `.knowledge-catcher.yml`.

Chunks сохраняются в SQLite. Изменение параметров меняет index
signature и при следующей ручной или автоматической синхронизации запускает
полный локальный rebuild индекса vault. Если последняя GitHub-проверка ещё
свежая, rebuild выполняется из сохранённого Markdown без лишнего GitHub-запроса.

Внутренний SQLite FTS5-индекс включает title, path, tags,
headings и тексту chunks. Отдельной пользовательской команды поиска пока нет:
FTS используется как источник candidates общего RAG-flow и как fallback
при недоступном semantic index.
Проекция поддерживается автоматически вместе с chunk index и используется
только при совпадении текущей index signature.

## Настройки embeddings

LLM Obsidian и embeddings настраиваются независимыми группами. Например, для LLM:

```dotenv
OPENAI_BASE_URL=https://api.timeweb.ai/v1
OPENAI_API_KEY=replace-me
OPENAI_MODEL=dashscope/qwen3.5-flash
```

Для embeddings:

```dotenv
EMBEDDING_BASE_URL=https://api.timeweb.ai/v1
EMBEDDING_API_KEY=replace-me
EMBEDDING_DOCUMENT_MODEL=openai/text-embedding-3-large
EMBEDDING_QUERY_MODEL=openai/text-embedding-3-large
```

Compose и Python берут каждый ключ из одноимённой переменной. Одинаковые
значения можно задать явно в обеих переменных; автоматической подстановки нет.
Полностью пустая LLM-группа разрешает общие команды, а Obsidian сообщает,
что анализ/review недоступны. Частичная группа останавливает запуск и называет
отсутствующее поле. Если Obsidian отключён, все его группы игнорируются,
включая некорректные настройки, и клиенты провайдеров не создаются.

На уровне приложения embedding-группа опциональна, но при заполнении хотя бы
одного параметра должны быть заданы все четыре. Для FTS fallback оставьте
все семь `EMBEDDING_*` пустыми, как в новом шаблоне. Documents и query должны обрабатываться
совместимой парой моделей:
adapter дополнительно проверяет совпадение dimension их ответов. Healthcheck
проверяет форму конфигурации без сетевого и платного embedding-запроса.
Vectors сохраняются в SQLite после каждого успешного batch. Сбой следующего
пакета не удаляет предыдущие checkpoints, в том числе после перезапуска процесса.
Повторная синхронизация отправляет только chunks без совместимого vector.
Global embedding marker публикуется после проверки полного покрытия; до этого
готовые source/FTS используются через FTS fallback. Повтор остаётся у ручного
`/vault_sync`, post-commit обновления и проверки после шестичасового окна.
Если lease истёк или перешёл другому процессу, текущая операция останавливается;
уже сохранённые checkpoints доступны следующему запуску.

Для оценочной стоимости в логах можно дополнительно задать весь тарифный блок:

```dotenv
EMBEDDING_PRICE_PER_MILLION_TOKENS=45
EMBEDDING_PRICE_CURRENCY=RUB
EMBEDDING_TARIFF_VERSION=2026-08-04
```

Цена — стоимость миллиона входных токенов в выбранной валюте, а версия — дата
или внутреннее имя тарифа, по которому потом можно проверить расчёт. Все три
поля опциональны, но задаются только вместе. Без них embeddings работают как
обычно, `usage` продолжает логироваться, а `estimated_cost` имеет значение
`none`. Значение нужно сверять с текущим кабинетом провайдера: именно кабинет,
а не локальная оценка, остаётся источником истины фактического списания.
