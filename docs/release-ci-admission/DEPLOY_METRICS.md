# Метрики выкладки

Для каждого выпуска сравниваем, сколько времени заняла выкладка и сколько
токенов потратил Codex. Разбивка по этапам помогает понять, что изменилось.
Документ задаёт правила для исходного замера и последующих сравнений.

## Что сравниваем

| Показатель | Как считать |
| --- | --- |
| Длительность выкладки | Прошедшее время от начала работ по установке выбранного опубликованного релиза до подтверждения живых ответов Telegram и VK. Включает ожидания, повторы и восстановление в рамках этой выкладки. Для незавершённой выкладки указываем время до остановки и её результат. |
| Токены Codex | Токены, относящиеся к работе над этой выкладкой в тех же границах. Сохраняем источник и фактический охват замера. Если расход нельзя достоверно отделить от остальной работы в чате, указываем `unknown`. |

Разработка, CI до публикации релиза и обновление базы CI после приёмки
лежат за границами этого замера. Для каждой записи указываем версию,
SHA и результат. Выкладки с восстановлением помечаем отдельно, чтобы
сравнение штатных выпусков учитывало одинаковый сценарий.

## Чем объясняем разницу

Если источники дают достаточно данных, фиксируем начало и конец этапа,
результат и ссылку на источник. В первую очередь смотрим допуск, backup
и миграции, запуск ботов, финализацию и приёмку. Ожидания, повторы,
восстановление и запросы к GitHub помогают объяснить отдельные задержки.
Время всей выкладки считаем по её началу и концу, поскольку этапы
в журналах могут пересекаться.

Начальный источник для разбивки на VPS — [метрики `deploy-prod`](../../scripts/deploy_metrics.py).
После проверки существующих данных определим, каких отметок не хватает.
Токены по отдельным этапам показываем, только если источник позволяет
достоверно их разделить.
