# Описать действия экрана и раздела

Этот документ фиксирует контракт, который ядро и адаптеры подключают на этапе 2 [плана](PLAN.md). После подключения владельцы экранов используют его для переноса [сценариев](INVENTORY.md). Типы, привязка ядра и Telegram подключены; проекция VK и общий сквозной набор проверяются следующими шагами.

## Вернуть доступные действия

Владелец экрана продолжает возвращать `IncomingResponse.suggested_actions` из `ReplyAction`. В одном месте он выбирает доступные действия и задаёт подпись, точную команду или HTTP(S)-ссылку, область и назначение. `SECTION` описывает действия раздела, `SCREEN` — действия показанного сообщения. `SELECTION` всегда принадлежит сообщению. `NAVIGATION` указывает `ScreenDestination` с именем экрана и необязательной страницей; исполняется всё равно исходная команда, адаптер не синтезирует её по назначению.

Адресные подтверждения остаются в `IncomingResponse.actions` из `ConfirmationAction`. Их публичный снимок, код подтверждения и владелец команды продолжают проверяться штатным путём. `ReplyAction` не заменяет адресный контракт подтверждений. Показ кнопки не заменяет проверку допуска, членства и актуальности выбора при исполнении.

`ResponseView` и подтверждение доставки сохраняют роль границы поколений адресного выбора. Адаптер не снимает предыдущие кнопки до подтверждения замены. URL открывает внешнюю страницу и не поступает в обработчик команд.

## Запросить меню отдельно от ответа

`SectionActionsQueryPort.section_actions` читает текущие действия раздела для проверенных профиля, чата, ревизии режима и ожидания ввода. Владелец использует общий построитель для этого запроса и экрана, без второго каталога подписей и целей. Запрос ничего не исполняет и не отправляет сообщение. Каталог `CapabilityHelp` сохраняет назначение справки и командного меню Telegram.

Пустой проверенный кортеж означает отсутствие доступных действий раздела. `SectionMenuDelivery.RECONCILE` сверяет этот набор с доставленным меню: отсутствие действий снимает прежнее меню, совпадение сохраняет его. `PRESERVE` оставляет меню без запроса нового набора. Ответ без действий сам по себе не добавляет кнопки. Ошибка чтения набора не равна пустому снимку.

`ChannelMessageProcessor.section_actions` предоставляет отдельный запрос без исполнения текста события. `CommandMenu.section_actions` переносит проверенный набор рядом с каталогом команд: `None` означает ещё не перенесённого владельца, пустой кортеж — раздел без действий. Ошибка источника оставляет доставку содержательного ответа без новой клавиатуры; она не публикует пустое меню. Ядро использует уже найденные профиль, режим и ожидание; только для нового порта дополнительно проверяет неизменность допуска вокруг предметного чтения.

Пока реальные экраны переносятся по этапам, прежние вызовы `ContextualCommandMenuPort` и значение `prefer` нужны действующим callers. Они удаляются после перевода этих callers; новый код использует описание действий и `RECONCILE`/`PRESERVE`. При наличии нового порта старый контекстный построитель меню не вызывается. Значение `None` у старого ответа продолжает обозначать обычную сверку меню.

## Проверить привязку перед показом

Ядро переносит назначение, область и цель перехода в `BoundReplyAction`; адаптер сериализует только этот проверенный набор. Точная команда хранится на сервере, в callback отправляется непрозрачный токен. Исполнение повторно проверяет профиль, чат, ревизию режима, доступ и адресное подтверждение. Действие `SELECTION` требует `ResponseView` и подтверждённого сообщения; без него остаётся текстовый путь.

URL не создаёт исполняемый токен. Он доступен в `bound_actions` только при сохранении профиля, режима, ревизии и допуска исходного владельца; при смене контекста ссылочный шаг нужно сформировать заново в новом контексте. Исходная URL-кнопка удаляется из `suggested_actions`, в том числе при отказе привязки, устаревшем представлении и позднем фоновом ответе. Это не меняет буквальные ссылки в содержимом сообщения.

## Сформировать страницу до доставки

Адаптер предоставляет нейтральные `ActionLayoutLimits` через `IncomingEvent.action_layout`, ядро передаёт их в `HandlerContext.action_layout`, включая продолжение ввода. Владелец вызывает `selection_capacity`, резервирует ряды и кнопки переходов, ограничивает результат своим размером страницы и лишь затем формирует текст, номера и точные цели. Адаптер не обрезает готовую страницу и не перенумеровывает выбор. При нулевой вместимости владелец сохраняет текстовую страницу и ручной путь; ограничения кнопок не запрещают текстовый выбор.

Например, шесть рядов и два служебных ряда оставляют четыре позиции, по одной на ряд. Видимые номера второй страницы остаются связанными с теми же предметными ID. Текстовые команды и предметная сверка доставленного снимка принадлежат владельцу сценария.

## Проверить подключение

Telegram передаёт ограничения до формирования экрана для текстового сообщения, фото и callback: 100 кнопок, до 8 в ряду, бюджет 100 рядов и проектный предел компактной подписи 64 символа. Число кнопок и ширина совпадают с ограничениями установленного `aiogram` (`InlineKeyboardBuilder`); лимит подписи является правилом приложения. Callback проверяется по пределу 64 байта UTF-8, URL и callback взаимоисключающие, как требует [Bot API](https://core.telegram.org/bots/api#inlinekeyboardbutton). Общий контракт использует HTTP(S)-ссылки. При отключённых кнопках вход передаёт нулевую вместимость.

Проекция Telegram сохраняет исходный порядок действий обоих scope и явно объединённые ряды. Повторный несмежный ряд или превышение лимита отключает клавиатуру целиком; готовые текст и номера не обрезаются. Клавиатура ставится на последнюю часть ответа. При управляемой замене новое поколение активируется после подтверждения последней части; при ошибке сохраняется старый экран. Неуправляемые исходные кнопки также снимаются лишь после доставки нового ответа. При редактировании пустой набор снимает клавиатуру вместе с изменением текста.

Проверки [проекции Telegram](../../tests/test_telegram_screen_actions.py) покрывают URL, callback, лимиты, отсутствие кнопок, ручной путь, многочастную замену, редактирование, устаревший резерв и сбой доставки. Каталог команд Telegram продолжает использовать `CommandMenu.items`; набор раздела не заменяет справку.

Первый шаг этапа проверяет типы и ограничения в [тестах контракта](../../tests/test_screen_action_contracts.py). [Проверки ядра](../../tests/test_screen_actions_core.py) используют временную БД с актуальными миграциями и проверяют отдельный запрос, допуск, единственность адресного выбора, сбой замены и отсутствие URL после отказа. Следующие шаги проводят главное меню, адресный выбор и обычный текст через доставку обоих каналов. До них проверки ядра не служат доказательством размещения или снятия клавиатур реальным адаптером.
