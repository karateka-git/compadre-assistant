# Этап 3.2: включить кэш загрузок pip

Запись от 01.11.2026 описывает минимальную правку выбранного в [аудите](STAGE3_AUDIT.md) узкого места и проверки перед сравнением шага 3.3. Правила допуска остаются в [RELEASES.md](../RELEASES.md); эта запись не подтверждает ускорение GitHub Actions.

## Проверить границу изменения

В [pr-fast.yml](../../.github/workflows/pr-fast.yml) к существующему `Setup Python` только job `pr-fast` добавлены `cache: pip` и `cache-dependency-path: requirements.txt`. Checkout тестового merge предшествует setup, поэтому путь указывает на корневой файл зависимостей проверяемого дерева. Команда установки полного `requirements.txt`, все проверки, их условия, таймауты и остальные jobs сохранены.

Контракт проверен по [README закреплённого setup-python v6.0.0](https://github.com/actions/setup-python/blob/e797f83bcb11b83ae66e0230d6156d7c80228e7c/README.md#caching-packages-dependencies): `pip` сохраняет глобальный каталог кэша, а не установленное окружение. Поэтому установка остаётся обязательной при попадании в кэш. Согласно [реализации ключа этой версии](https://github.com/actions/setup-python/blob/e797f83bcb11b83ae66e0230d6156d7c80228e7c/src/cache-distributions/pip-cache.ts), основной ключ включает ОС, архитектуру, Linux distribution/version, разрешённую версию Python, менеджер `pip` и hash файла зависимостей. Собственный ключ не добавлен. При изменении файла меняется основной ключ; restore-prefix допускает частичное восстановление предыдущего кэша, после которого pip всё равно устанавливает текущие требования.

Ожидаемый эффект — сокращение повторной загрузки пакетов. Установка и разрешение зависимостей остаются, а восстановление и сохранение кэша добавляют время. Прямые зависимости закреплены версиями, но файл не является полным lock транзитивных зависимостей. Кэш не гарантирует ни одинакового набора транзитивных версий между runs, ни ускорения. Фактический эффект пока **unknown**.
