# v3.1.0 — базовый runtime для будущего безопасного возврата

## Изменения

- Добавлен ограниченный runtime-допуск проверенной будущей схемы SQLite:
  точные SHA, image ID, controller SHA, журнал миграций и fingerprint схемы
  должны совпасть с независимым launch context. При отсутствии допуска
  действует прежняя строгая проверка; неизвестный SQL runtime не исполняет.
- Неизвестные значения статусов и действий из БД/API переходят в UNKNOWN.
  Затронутые операции статей, proposal, vault и Device Flow безопасно
  отказывают до действий, для которых нужен известный смысл значения.
- Добавлены короткие отчёты CI по SHA/run/attempt и времени jobs/steps,
  предупреждения долгих шагов и приватные метрики deploy, включая простой.
- Измерен pip cache короткого PR-пути: ускорение не подтвердилось,
  настройка кэша удалена. Установка зависимостей, полный набор тестов
  и строгий допуск точного выпускного SHA сохранены.

## Установка и ограничения

Миграции `0001`–`0004` не изменены, новых SQL нет. Данные сохраняются.
Версия готовит базовый runtime; она ещё не включает автоматический возврат
старого образа на будущую production-схему. Для этого отдельно нужны
проверка точной пары образов и доставка допуска доверенным контроллером.
Перечень проверенных production-пар пока пуст.

Метрики deploy требуют отдельного обновления установленного controller
snapshot. Публикация этого Release не меняет VPS; установка выполняется
отдельной командой `deploy-prod v3.1.0` после эксплуатационной проверки.

Локальная проверка: 1036 unittest, два Linux-only теста (flock/systemd)
пропущены при локальном запуске на Windows, три автономных smoke. Выпуск разрешён
только после успешного полного `main-full` фактического merge SHA, включая
Linux/container проверки; его run/attempt фиксирует публикационный скрипт.
