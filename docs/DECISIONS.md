# Действующие решения и их причины

Здесь кратко объясняется, почему выбраны нынешние границы системы. Фактическое
поведение и контракты описаны в [ARCHITECTURE.md](ARCHITECTURE.md), порядок
выпуска — в [RELEASES.md](RELEASES.md), команды эксплуатации — в
[OPERATIONS.md](OPERATIONS.md). Датированные планы и отменённые варианты сюда
не входят.

| Решение | Причина |
| --- | --- |
| Python, Compose, `aiogram`, `trafilatura`, `sqlite3` | Python объединяет bot polling, извлечение статей и поиск без отдельного сервиса для обработки текста. Compose даёт одинаковую форму локального и серверного запуска; SQLite соответствует нынешней нагрузке проекта и прозрачно управляется миграциями. |
| Ядро и явно подключаемые возможности, слои `domain`/`data`/`presentation` | Каналы, идентичность и маршрут чата общие, а правила Ask и Obsidian независимы. Порты отделяют сценарии от SDK, SQL и внешних API; явная регистрация делает состав процесса проверяемым. |
| Отдельный режим на чат, общий профиль пользователя | Один пользователь работает в Telegram и VK с общими данными, не смешивая контексты разных чатов. Адрес и версия ожидающего действия предотвращают подтверждение устаревшего или чужого действия. |
| GitHub App как источник доступа к vault | Installation token ограничен выбранным repository и живёт недолго; постоянный пользовательский token не нужен. GitHub остаётся источником истины, SQLite хранит рабочую копию и состояние сценариев. |
| Подтверждаемый `add`/`update`/`skip` | LLM может ошибиться. Сохранённый proposal и предварительная проверка GitHub SHA дают человеку возможность увидеть текст и не перезаписать чужое изменение. |
| Инкрементальный snapshot и локальный поиск | Повторно скачивать и индексировать неизменённый vault дорого. Проверка нового snapshot до применения сохраняет последнюю пригодную копию при сбое GitHub или правил. |
| FTS5 и optional embeddings | FTS5 даёт доступный точный поиск без внешнего API. Semantic vectors улучшают релевантность, но частичные batches не объявляются готовым индексом; при сбое используется явный FTS fallback. |
| SQLite lease и короткие operation scopes | Telegram и VK могут одновременно работать с одним vault. Lease ограничивает sync/write-back одним владельцем, а отдельные соединения не переходят между worker threads и долгими сетевыми вызовами. |
| Закреплённый выпуск с отдельной установкой на VPS | Публикация Release фиксирует проверенный SHA, но сервер обновляется только отдельной контролируемой командой. Backup, миграции и оба канала проверяются как одна операция; неуверенный возврат блокирует следующий deploy. |

Применённую в production `0001_initial_schema.sql` не меняют: последующие
изменения схемы оформляют миграциями `0002+` с сохранением данных. Временное
разрешение пересоздавать отдельную development-БД описано в
[AGENTS.md](../AGENTS.md) и [RUN.md](RUN.md); оно не относится к VPS.
