# Ядро: сценарии и тексты

Каждая схема сразу сопровождается текущими текстами ответов. Метки на схеме совпадают с ID в таблице ниже. Общий путь сообщения показан в [маршруте](RESPONSE_MAP.md). В колонке «Целевой текст» пока нет согласованной редакции.

## Первый запуск, регистрация и имя

```mermaid
flowchart TD
    A[Сообщение из канала] --> B{Профиль известен?}
    B -->|нет, start| C[П1: приветствие и выбор регистрации]
    B -->|нет, иное сообщение| D[П2: неизвестный канал]
    C --> E{register или link?}
    D --> E
    E -->|register| F[П3: профиль создан, нужно имя]
    E -->|link| G[Привязка второго канала]
    F --> H{Имя допустимо?}
    H -->|нет| I[П4: правила имени]
    H -->|да| J[П5: регистрация завершена и доступны входы]
    B -->|да, start| K{Имя уже есть?}
    K -->|нет| L[П6: завершить регистрацию]
    K -->|да| M[П7: приветствие и доступные входы]
    B -->|да, register| N[П8: уже зарегистрирован]
    B -->|да, name| O{Имя допустимо?}
    O -->|нет| I
    O -->|да| P[П9: имя изменено]
```

## Привязка второго канала и перенос профиля

```mermaid
flowchart TD
    A[Пользователь: link_code] --> B{Код создан?}
    B -->|нет| C[К1: сбой создания]
    B -->|да| D[К2: код, команда и срок]
    D --> E[Пользователь в другом канале: link код]
    E --> F{Код и канал подходят?}
    F -->|нет аргумента| G[К3: форма команды]
    F -->|код неверен или истёк| H[К4: создать новый код]
    F -->|уже связан с тем же профилем| I[К5: уже привязан]
    F -->|свободен| J[К6: канал привязан]
    F -->|связан с другим профилем| K[К7: запрос переноса с адресными командами]
    K --> L{Решение в исходном чате}
    L -->|да| M[К8: перепривязан]
    L -->|нет| N[К9: старая привязка сохранена]
    L -->|устарело или неверная команда| O[К10: причина и повтор link]
```

## Справка, статус и режим чата

```mermaid
flowchart TD
    A[Пользователь: help] --> B{Есть профиль?}
    B -->|нет| C[Р1: справка до регистрации]
    B -->|да| D{Режим этого чата}
    D -->|main| E[Р2: общие команды и доступные входы]
    D -->|активный Obsidian| F[Р3: команды Obsidian, общая подсказка и exit]
    D -->|сохранённый, но недоступный| G[Р4: причина недоступности и выход]
    H[Пользователь: status] --> I[Р5: профиль, режим и доступные входы]
    J[Пользователь: exit] --> K[Р6: режим очищен в этом чате]
    L[Обычный текст в main] --> M[Р7: выбрать доступный вход]
    N[Обычный текст в недоступном режиме] --> G
    O[Адресная confirm вне исходного режима] --> P[Р11: войти в исходный режим]
```

Р1–Р4 — целевое поведение задачи; текущий `/help` ещё не различает режимы.
Его исходный полный список находится в реестре как шаблон `Р0`.

```mermaid
flowchart TD
    A[Пользователь: capabilities] --> B{Есть профиль?}
    B -->|нет| C[В1: сначала регистрация]
    B -->|да, без аргумента| D[В2: каталог и состояния]
    B -->|да, с аргументом| E[В3: вызвать без аргументов]
    F[Пользователь: enable или disable] --> G{Один известный ID?}
    G -->|нет аргумента| H[В4: точная форма команды]
    G -->|неизвестен| I[В5: неизвестная возможность]
    G -->|да| J{Есть доступ на сервере при enable?}
    J -->|нет| K[В6: сервер недоступен, выбор сохранён]
    J -->|да или disable| L{Запись выполнена?}
    L -->|нет| M[В7: ошибка сохранения]
    L -->|да, изменено| N[В8: новое состояние во всех каналах]
    L -->|да, уже так| O[В9: выбор уже установлен]
    P[Пользователь вызывает выключенный вход] --> Q[В10: причина и доступное действие]
```

## Подстановки и следующий шаг

В таблицах ниже указаны только переменные данные и действие после ответа;
текущие тексты остаются в реестрах выше.

| ID | Переменные данные | Следующий шаг пользователя |
| --- | --- | --- |
| П1–П2 | Нет. | Выбрать `/register` либо ввести полученный в другом канале код через `/link <код>`. |
| П3, П6 | Имя ещё не задано. | Ввести имя следующим обычным сообщением; это работает и после перезапуска, пока у профиля нет имени. |
| П4 | В примере подставлено имя `Влад`; введённое недопустимое значение не повторяется. | Исправить имя и отправить его снова. |
| П5, П7, П8 | Имя профиля и доступные команды входа. | Выбрать команду входа из подсказки; для П7/П8 дополнительных действий нет, если вход не нужен. |
| П9 | Сохранённое имя профиля. | Дополнительное действие не требуется. |
| К1, К3–К6, К9, К10а | Нет. | К1: повторить `/link_code`; К3: ввести код; К4: создать новый `/link_code`; К5–К6 и К9: действие завершено; К10а: использовать актуальную адресную команду из запроса переноса. |
| К2 | Одноразовый код; срок действия — 10 минут. | В другом канале ввести `/link {код}` до истечения срока. |
| К7 | ID и версия подтверждения; обе адресные команды содержат эти значения. | В исходном канале выполнить точную команду переноса или отмены из ответа в течение срока действия подтверждения (10 минут). |
| К8 | Имя целевого профиля, если оно задано. | Перепривязка завершена; дополнительное действие не требуется. |
| К10б | Нет. | Повторить `/link` в исходном чате; старое подтверждение использовать нельзя. |
| Р0 | Общий список команд, эффективные входы, их описания и команды возможностей. | Выбрать подходящую команду из справки. Для неизвестного канала выбрать `/register` или `/link <код>`. |
| Р1–Р4 | Целевые ветки; сейчас вместо них показывается Р0. | Следующий шаг определяется выбранной командой Р0; текущая справка не выдаёт отдельный сценарий режима. |
| Р5 | Имя/состояние имени, ID режима, доступные входы и при недоступности причина из В10. | Использовать подсказанную команду; если режим выбран ошибочно, вызвать `/exit`. |
| Р6 | Подсказка доступных входов. | Выбрать вход, если нужно продолжить работу. |
| Р7а | Доступные команды входа. | Вызвать одну из показанных команд. |
| Р7б | Нет. | Открыть `/capabilities` или `/help`; доступного входа сейчас нет. |
| Р8 | Причина недоступности и доступные команды входа. | Вызвать `/exit` либо выбрать доступный вход. |
| Р9 | Техническая ошибка не выводится. | Повторить вход позже или вызвать `/help`. |
| Р10 | Техническая ошибка не выводится. | Проверить состояние действия, затем решить, безопасно ли повторить сообщение. |
| Р11 | Команда входа, если она доступна. | В исходном чате вызвать эту команду и продолжить подтверждение; если вход недоступен, перейти по подсказке Р7. |
| Р12 | Нет. | Вызвать `/help`. |
| В1, В3–В5, В7 | В В3–В5 подставляются команда и/или ID; текущее неизвестное значение не повторяется. | В1: зарегистрироваться; В3: вызвать `/capabilities` без аргументов; В4: открыть список и ввести один ID; В5: выбрать известный ID; В7: повторить позже. |
| В2 | Каталог ID, описания, личный выбор и доступность сервера; при пустом каталоге данных нет. | Выбрать ID и вызвать `/enable <id>` или `/disable <id>`. |
| В6 | ID возможности. | Серверная возможность недоступна; повторить `/capabilities` позже, личный выбор не изменён. |
| В8–В9 | ID и состояние личного выбора. | Выбор завершён; дополнительное действие не требуется. |

отправлен `/link`. Для него требуется точная адресная команда с ID и версией
из К7; простые `да`/`нет` ядро для переноса не принимает. Код и подтверждение
действуют 10 минут.
