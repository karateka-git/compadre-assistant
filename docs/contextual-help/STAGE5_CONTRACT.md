# Проверить единый контракт ответа — шаг 5.5

Этот отчёт фиксирует локальную проверку шага 5.5 из [плана](PLAN.md) на
26.10.2026. Для
проверки исходных сообщений используйте [реестры](RESPONSE_MAP.md),
[проект представления](FORMATTING_DESIGN.md) и [гарантии рендереров](STAGE5_RENDERERS.md).
Проверки ниже относятся к текущему worktree `codex/contextual-help-implementation`,
а не к фактическому виду сообщений в клиентах Telegram и VK.

## Сверить покрытие реестров

Указанные строки существуют в коде и проходят через `MessageContent` и
единый путь рендеринга немедленного или фонового ответа. Диапазоны ID
сверены с таблицами четырёх реестров. Это карта реализованных путей,
а не отдельный тест каждого условия. Для строк «без
изменений» проверяется сохранение смысла и переменных данных; изменение
сценария, помеченное в реестре как целевое для этапа 6, здесь не заявляется.

## Проверить локальный результат

`IncomingResponse` содержит только `content`, `error` и `actions`. Временный
`render_text()`, строковые функции `split_telegram_message()` и
`split_vk_message()` и их вспомогательные функции удалены из работающего
кода. Поиск в `compadre_assistant` и `tests` не находит вызовов старого API.
Старые имена в отчётах этапа 3 обозначают историческое состояние.

Профильный прогон через проектный `.venv` — 71 тест, успешно. Полный прогон
`python -m unittest discover -s tests` — 782 теста, успешно, 2 пропуска.
`git diff --check` не выявил ошибок пробелов; Git предупредил только о
будущей замене LF на CRLF в `tests/response_assertions.py`.

Профильные тесты сравнивают видимый текст Telegram и VK, точные адресные
команды, экранированные динамические значения, немедленный и фоновый путь,
передачу HTML/`format_data` в API, порядок частей и существующие правила
повтора. В полном прогоне обновлён тест, который раньше принимал Telegram
HTML-тег `</code>` за часть кода привязки; теперь он сравнивает видимый текст.

## Завершить живую проверку на этапе 8

В личных диалогах обоих каналов проверить фактический вид выделения, команд,
переносов и длинных ответов после окончательного подключения сценариев.
Для Telegram отдельно проверить экранирование подставленных спецсимволов,
закрытие HTML-тегов и частичную доставку. Для VK проверить `format_data` на
API 5.199 с кириллицей и emoji, offsets после emoji/combining/ZWJ, границы
частей и вид в клиенте. До такой пробы renderer оставляет сложные Unicode
части без `format_data`. Меню, кнопки, callback/ack и актуальность действий
проверяются после этапа 7. При неопределённой ошибке отправки не посылать
запасную копию всего ответа.
