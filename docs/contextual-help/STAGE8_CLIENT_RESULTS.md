# Результаты клиентской приёмки этапа 8

Этот журнал сопоставляет наблюдения владельца в личных клиентах Telegram и VK с [матрицей приёмки](STAGE8_ACCEPTANCE_MATRIX.md). Процедура переключения и состояние окружения записаны в [передаче окна](STAGE8_HANDOFF.md). Автоматические тесты шага 8.2 не заменяют приведённые здесь клиентские наблюдения. Секреты, ID личных диалогов и тексты переписки не сохраняются.

Для этого окна используется локальный образ `compadre-assistant:contextual-help-stage8-3d356629d142` и отдельная development-БД `data/stage8-probe-1`. По разрешению владельца локальные контейнеры перезапущены с Obsidian и Ask; значения профиля Ask переданы только через окружение процесса из существующих `OPENAI_*`, без нового файла. Healthcheck этой конфигурации прошёл, оба polling-процесса стартовали без ошибок запуска.

Перед локальным запуском обнаружено, что production unit снова стала `active` после предыдущей остановки; сервер не перезагружался, причина запуска не установлена. Точный production checkout остался на `v2.0.0`, оба контейнера были `healthy`. Unit повторно остановлена, после чего подтверждены `inactive` и отсутствие работающих Compose-контейнеров. Дальнейшие пробы требуют повторной проверки отсутствия второго polling.

В локальном Telegram-контейнере один раз зафиксирован `sqlite3.OperationalError: unable to open database file` при фоновой сверке известных чатов для меню. Обработка сообщений продолжилась, повторный доступ к SQLite из обоих контейнеров прошёл. Причина и повторяемость не установлены; ошибку нельзя считать закрытой только по успешному ответу Ask.

## Проверить VK — 29.10.2026

| Сценарий | Наблюдение владельца | Результат |
| --- | --- | --- |
| Неизвестная identity: `/help` | Ответ содержит только `/register` и `/link`; отдельная клавиатура с этими командами видна возле поля ввода. | Пройдено для личного VK-клиента. |
| `/register`, тестовое имя, `/help` | Бот запросил имя, затем создал профиль; клавиатура сменилась с двух команд на основной список. | Пройдено. |
| `/name` без аргумента, `/help`, `/cancel` | Ожидание нового имени и его отмена прошли по ожидаемому сценарию. | Пройдено; вид клавиатуры на этом переходе отдельно не описан. |
| `/enable` без аргумента | Бот предложил `obsidian`, но постоянная клавиатура показывала только общий список команд и `/cancel`; отдельной кнопки выбора не было. Служебное сообщение сообщало об обновлении меню. | Обнаружено UX-расхождение; исправление требует повторной клиентской пробы. |

Промежуточная сборка показала `obsidian` в начале постоянной клавиатуры и кнопку «Включить obsidian» под ответом. Владелец нажал кнопку постоянной клавиатуры: возможность включилась, временная кнопка исчезла, `/obsidian` открыл режим. Затем владелец выбрал единый вид для Telegram и VK: временный выбор только inline под ответом. Постоянная клавиатура VK снова содержит лишь команды, включая `/cancel` при ожидании. Итоговую сборку и inline-нажатие ещё нужно проверить в клиентах.

В итоговой сборке inline-кнопка «Выключить obsidian» была видна, но нажатие не дало ответа и не убрало кнопку. Короткий наблюдатель VK Long Poll получил `message_event` без вывода ID и payload: поля `peer_id`, `user_id`, `event_id` и `conversation_message_id` имели ожидаемые типы, а `payload` оказался объектом `dict`. Адаптер принимал только JSON-строку и пропускал это событие до выбора действия. Исправление добавлено и покрыто адресным тестом; повторное клиентское нажатие после новой сборки ещё требуется.

## Продолжить приёмку

1. Завершить проверки Telegram: оформление, длинные ответы, безопасное подтверждение с кнопкой и вид меню после ответа Ask в клиенте. Проверить, повторяется ли ошибка фоновой сверки меню.
2. Повторить VK `/enable` и `/disable` после удаления временного ID из постоянной клавиатуры; проверить inline-кнопку, справку и меню в режиме, Ask, `format_data` и повторное нажатие. Аналогичные inline-кнопки проверить в Telegram.
3. Для каждого пропущенного сценария указать причину; расхождения передать шагу 8.6. Возврат на VPS выполнять только по отдельному указанию владельца и порядку [шага 8.7](PLAN.md#этап-8-проверить-сценарии-и-оформление).
