# Результаты клиентской приёмки этапа 8

Этот журнал сопоставляет наблюдения владельца в личных клиентах Telegram и VK с [матрицей приёмки](STAGE8_ACCEPTANCE_MATRIX.md). Процедура переключения и состояние окружения записаны в [передаче окна](STAGE8_HANDOFF.md). Автоматические тесты шага 8.2 не заменяют приведённые здесь клиентские наблюдения. Секреты, ID личных диалогов и тексты переписки не сохраняются.

Для этого окна используется отдельная development-БД `data/stage8-probe-1`. По разрешению владельца локальные контейнеры запущены с Obsidian и Ask; значения профиля Ask переданы только через окружение процесса из существующих `OPENAI_*`, без нового файла. Текущий образ — `compadre-assistant:contextual-help-stage8-5109996`; после повторного запуска оба polling-процесса стартовали без ошибок. Предыдущий образ `727b69a` прошёл healthcheck этой конфигурации; новую сборку проверили полным набором тестов и запуском обоих каналов.

Перед локальным запуском обнаружено, что production unit снова стала `active` после предыдущей остановки; сервер не перезагружался, причина запуска не установлена. Точный production checkout остался на `v2.0.0`, оба контейнера были `healthy`. Unit повторно остановлена, после чего подтверждены `inactive` и отсутствие работающих Compose-контейнеров. Дальнейшие пробы требуют повторной проверки отсутствия второго polling.

В локальном Telegram-контейнере один раз зафиксирован `sqlite3.OperationalError: unable to open database file` при фоновой сверке известных чатов для меню. Обработка сообщений продолжилась, повторный доступ к SQLite из обоих контейнеров прошёл. Причина и повторяемость не установлены; ошибку нельзя считать закрытой только по успешному ответу Ask.

Промежуточная сборка показала `obsidian` в начале постоянной клавиатуры и кнопку «Включить obsidian» под ответом. Владелец нажал кнопку постоянной клавиатуры: возможность включилась, временная кнопка исчезла, `/obsidian` открыл режим. Затем владелец выбрал единый вид для Telegram и VK: временный выбор только inline под ответом. Постоянная клавиатура VK снова содержит лишь команды, включая `/cancel` при ожидании. Inline-нажатие итоговой сборки проверяется отдельно.

В сборке до исправления inline-кнопка «Выключить obsidian» была видна, но нажатие не дало ответа и не убрало кнопку. Короткий наблюдатель VK Long Poll получил `message_event` без вывода ID и payload: поля `peer_id`, `user_id`, `event_id` и `conversation_message_id` имели ожидаемые типы, а `payload` оказался объектом `dict`. Адаптер принимал только JSON-строку и пропускал это событие до выбора действия. Исправление коммита `727b69a` добавило обработку обеих форм payload; полный прогон — 983 теста, `OK (skipped=2)`.

После перезапуска с образом `727b69a` владелец повторил `/disable` и нажал новую inline-кнопку. Бот ответил об отключении Obsidian, кнопка исчезла. Следующая кнопка «Включить obsidian» сработала со второй попытки и с задержкой; ошибок в локальном VK-журнале не было. Причина задержки пока не установлена. Владелец подтвердил сохранение постоянной клавиатуры и безопасный отказ при повторном нажатии старой кнопки.

Текущие renderer и API-клиенты отправили синтетическую пробу оформления по одному сообщению в каждый канал. Telegram-сериализация содержала выделение `Жирный` и CODE-фрагмент `/help`; VK отправил диапазон `format_data` для выделения. На скриншотах владельца жирное выделение, буквальные маркеры и переносы видны в обоих каналах; `/help` выглядит синим в Telegram и обычным текстом в VK. Владелец уточнил, что именно отсутствие моноширинного вида команды VK считает расхождением. Дополнительная проба типа `code` в VK API была принята без ошибки, но владелец подтвердил обычный вид в клиенте. VK-клавиатура не предоставляет действия копирования текста; по выбору владельца CODE-команды оформляются курсивом с сохранением буквального текста. В новом `/help` владелец увидел светло-серые русские подсказки внутри `<…>`. Контрольное VK-сообщение без `format_data` показало тот же вид, а английское `<text or URL>` осталось обычного цвета. По просьбе владельца подсказки аргументов в пользовательских ответах переведены на английский; результат в новом `/help` ещё не проверен. Затем те же renderer и API-клиенты отправили пронумерованный длинный текст: 2 части в Telegram, 3 в VK. Владелец подтвердил порядок 001–179 и конечную строку в обоих клиентах. Личные ID и секреты в отчёте не сохраняются.

## Продолжить приёмку

1. Завершить проверки Telegram: безопасное подтверждение с кнопкой. Проверить, повторяется ли ошибка фоновой сверки меню.
2. Завершить VK: проверить новые имена команд, широкую клавиатуру и английские подсказки в `/help`, затем режим и безопасное подтверждение. Зафиксировать, повторится ли задержка первого нажатия inline-кнопки.
3. Для каждого пропущенного сценария указать причину; расхождения передать шагу 8.6. Возврат на VPS выполнять только по отдельному указанию владельца и порядку [шага 8.7](PLAN.md#этап-8-проверить-сценарии-и-оформление).
