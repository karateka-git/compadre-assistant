# Перенос рабочих материалов в постоянную документацию

Этот список фиксирует, что из [рабочего плана](PLAN.md) должно остаться в
документации после реализации контекстной справки и новых текстов. Обновляй
статус строки по мере реализации, а не выбирай назначение документов в
последний день. Утверждённое поведение и ограничения переносим; черновые
примеры, которые не вошли в код, отмечаем как отклонённые с причиной.

| Рабочий источник | Что сохранить | Постоянное место | Статус |
| --- | --- | --- | --- |
| [Правила сообщений](MESSAGE_RULES.md), языковые решения из [плана](PLAN.md#принятые-решения-по-языку-и-справке) | Правила текста, контекста, структуры и оформления для будущих изменений | Новый `docs/USER_MESSAGES.md`; добавить на него ссылку из `AGENTS.md` | Ожидает реализации |
| [Маршрут сообщения](RESPONSE_MAP.md) | Маршрут ответа, условия выбора сценария и связь с реестрами | `docs/USER_MESSAGES.md`; архитектурную границу — в [ARCHITECTURE.md](../ARCHITECTURE.md) | Ожидает реализации |
| [Ядро](CORE.md), [Ask](ASK.md), [Obsidian](OBSIDIAN.md) | Проверенные пользовательские сценарии, схемы рядом с реестром и утверждённые формулировки | Новые `docs/user-messages/CORE.md`, `ASK.md`, `OBSIDIAN.md`; обзор для пользователя — в [README.md](../../README.md) | Ожидает редакции текстов |
| [Представление по каналам](FORMATTING_DESIGN.md) | Итоговый контракт `MessageContent`, обязанности адаптеров, безопасность данных и разбиение | [ARCHITECTURE.md](../ARCHITECTURE.md); правила видимого оформления — в `docs/USER_MESSAGES.md` | Ожидает реализации |
| [Выбор команд](COMMAND_HINTS.md) | Поведение команд без аргументов, контекстное меню, кнопки ответа, ожидание ввода и текстовый путь для канала без кнопок | [ARCHITECTURE.md](../ARCHITECTURE.md) для контрактов и состояния; [RUN.md](../RUN.md) для пользовательских шагов; `docs/USER_MESSAGES.md` для правил подсказок | Ожидает реализации |
| [План](PLAN.md) | Итоговые решения, которые не дублируются строками выше | Соответствующие постоянные документы; закрыть [пункт бэклога](../BACKLOG.md#контекстная-справка-help) последним шагом | Ожидает реализации |

`docs/USER_MESSAGES.md` и `docs/user-messages/` — запланированные пути, пока
этих файлов нет. Точные текущие и целевые ответы хранятся в рабочих
реестрах до завершения редакции. При переносе сверить каждый сценарий с
фактическим кодом и оставить в постоянном реестре только действующее
поведение; принятый текст не должен расходиться с отправляемым ботом.

## Как отмечать выполнение

1. После реализации части функциональности обнови её строку: укажи
   «перенесено» и ссылки на созданные разделы. Если решение было заменено,
   укажи «отклонено» и краткую причину вместо молчаливого удаления.
2. Перед закрытием задачи проверь сценарии, ссылки, команды и названия
   файлов в постоянных документах; затем отметь строку «проверено».
   Обнови [карту кода](../CODE_MAP.md), если появились новые точки входа.
3. Когда все строки проверены, перенеси ссылки на постоянные документы в
   README и связанные документы. Удаление `docs/contextual-help/` выполни
   отдельным завершающим изменением по [AGENTS.md](../../AGENTS.md).
