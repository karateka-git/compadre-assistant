# Дополнительная проверка оформления и меню — 25.10.2026

Этот отчёт уточняет результаты [этапа 3](PLAN.md) после вопросов владельца о
форматировании VK и меню Telegram. Пробы выполнены с существующими ботами в
личных диалогах. Токены и идентификаторы диалогов в отчёт не включены.

## Проверить оформление VK

Первоначальная проба передавала в `messages.send` только `message`. Маркеры
Markdown и HTML в этом режиме показывались буквально. Это не проверяло
отдельный параметр `format_data`.

В повторной пробе VK API принял сообщение с `format_data`: `version="1"`,
`items` с диапазонами `bold`, `italic`, `underline` и `url`. Для вызова с
`v=5.245` владелец подтвердил в клиенте жирный текст, курсив, подчёркивание
и кликабельную ссылку. Дополнительный вызов с `v=5.199`, закреплённой в
[VK-адаптере](../../compadre_assistant/presentation/vk/bot.py), выделил слово
жирным; это также подтверждено владельцем. Вызовы были адресованы только
личному диалогу владельца, найденному после его пробного сообщения.

Результат доказывает возможность форматировать ответы бота VK через
`format_data` в проверенном клиенте. Он не доказывает поддержку моноширинного
шрифта, поведение URL preview, корректность диапазонов после emoji и правила
разбиения длинных форматированных сообщений. Схема
[VK API 5.199](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json)
не содержит `format_data`; здесь решающим доказательством служит фактический
вызов API и вид сообщения в клиенте. Перед реализацией нужно выбрать
представление диапазонов, проверить границы на смешанном тексте и emoji, сохранить
обычный текст как путь при ошибке или неподдерживаемом стиле.

## Проверить меню Telegram

Read-only Bot API запросы к существующему боту вернули тип глобальной кнопки
`getChatMenuButton.type=commands`, тип личного чата `default` и пустые списки
`getMyCommands` для `default`, `all_private_chats` и личного scope. Текущий
адаптер не вызывает `setMyCommands`; поэтому клиенту было нечего показывать в
меню команд. Прежнее наблюдение «меню не открылось» не означало отсутствия
поддержки меню в Telegram.

После read-only проверки состояния VPS и связи VK/Telegram-личностей бот
опубликовал только для личного Telegram-чата владельца одну временную команду
`help` через `setMyCommands` с `BotCommandScopeChat`. `getMyCommands` вернул
эту команду, а владелец увидел пункт в меню и при вводе `/`. Затем
`deleteMyCommands` удалил временный личный scope; повторный запрос подтвердил
пустой список. Глобальный список не менялся.

Для реализации адаптер публикует записи команд через
[`setMyCommands`](https://core.telegram.org/bots/api#setmycommands) с
`BotCommandScopeChat` для личного чата. После вызова он сверяет этот scope
через `getMyCommands`, а владелец проверяет кнопку меню и список при вводе
`/` в клиенте. Глобальная кнопка уже имеет тип `commands`; менять её на Mini
App не требуется. Осталось реализовать обновление списка по контексту и
проверить устаревание/синхронизацию после изменения состояния.

## Проверить меню VK

Через `messages.send` с `keyboard` и `inline=false`, `one_time=false` бот
отправил текстовую кнопку `/help`. Владелец подтвердил её появление возле
поля ввода. Затем бот отправил пустую клавиатуру, и владелец подтвердил
исчезновение кнопки. При вводе `/` без отправки в проверенном клиенте VK
список команд не появился. Следовательно, для VK доступно меню в виде
клавиатуры диалога, но Telegram-подобная подсказка по `/` здесь не обнаружена.
В просмотренной [схеме методов VK API 5.199](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json)
нет метода публикации списка команд по образцу Telegram. Это наблюдение одного
клиента и одной версии схемы, а не доказательство невозможности во всех
версиях VK. Нажатие этой текстовой кнопки не проверялось. На этапе реализации надо
проверить обновление состава клавиатуры, действие кнопки и текстовый путь
без неё.
