# Результаты Telegram-пробы шага 3.3

Этот отчёт фиксирует переданные владельцем результаты Telegram-проверки
25.10.2026. Последовательность передачи polling и ограничения на production
описаны в [runbook](STAGE3_HANDOFF.md); общие контракты каналов — в
[сверке Telegram и VK](STAGE3_CHANNEL_CONTRACTS.md). Штатный адаптер и
синтетические probes отмечены отдельно: probe не подтверждает наличие функции
в штатном приложении.

## Состояние переключения

- Production unit остановлена в 06:59:42 UTC. При втором локальном запуске VK
  group ID совпал с production, но первоначальный локальный Telegram token
  принадлежал `@KnowledgeCatcher_bot`, а production использует
  `@CompadreAssistant_bot`.
- Root остановил ошибочный Telegram-контейнер и очистил старый token из основной
  локальной `.env`. Пользователь отдельно разрешил одноразовый защищённый
  перенос правильного Telegram token с VPS. Root записал его напрямую в
  основную локальную `.env`, не выводя и не логируя значение и не сохраняя его
  в Git. Read-only `getMe.username` подтвердил `CompadreAssistant_bot`.
- Оба локальных бота сейчас работают. По просьбе владельца production unit
  остаётся неактивной до отдельного указания о возврате, в том числе после
  завершения этапа 3; автоматического таймера возврата нет. Решение при
  техническом блокере принимается отдельно с владельцем.
- Результаты ниже получены от владельца, включая его подтверждение клиентского
  отображения; этот отчёт не означает независимый повторный просмотр клиента.

## Наблюдения в Telegram-клиенте

### `/help` и меню команд

В личном диалоге `/help` ответил в 13:06 по времени Омска. Показаны только
общие команды; переносы строк отображались правильно. Меню при вводе `/` не
открылось.

Read-only `getMyCommands` вернул пустые списки для `default`, `all_private_chats`
и chat scope. Никакие command scopes не меняли. Клиентское отсутствие меню
согласуется с этими ответами, но само по себе не устанавливает, почему меню не
открылось в клиенте.

### Обычный текст и HTML probe

В обычном тексте маркеры `**`, обратные кавычки и буквальный `<b>` отображались
как текст; переносы и emoji были видны. Штатный Telegram-адаптер отправляет
текст без `parse_mode`, поэтому это наблюдение относится к обычной доставке.

В отдельном synthetic probe с `parse_mode=HTML` жирный текст, моноширинный текст
и экранирование спецсимволов отображались правильно по пользовательскому
скриншоту. Это подтверждает результат конкретной HTML-пробы в этом клиенте, но
не означает, что текущий штатный адаптер включает HTML-разметку.

### Длинный текст

Штатный `split_telegram_message` разделил искусственный текст на две части
длиной 3868 и 2999 символов. Первая часть доставилась, а вторая при первой
попытке не была подтверждена API и не появилась в клиенте; точная причина не
установлена. После отдельной повторной отправки API
подтвердил доставку второй части; владелец подтвердил порядок строк до номера
110 и конечную метку. Следовательно, разбиение и повторная отправка проверены,
но первая попытка не доставила весь ответ как единый завершённый результат.

### Inline-кнопка и клавиатура

Inline-кнопка была видна в клиенте. После нажатия клиент оставался в состоянии
ожидания; штатный адаптер callback не обрабатывает. Вызов `editMessageReplyMarkup`
удалил кнопку, что подтвердил владелец.

Получение callback event, его payload и корректный ответ на callback не
подтверждены. Результат ограничивается отображением кнопки, отсутствием
наблюдаемого ответа приложения после нажатия и подтверждённым удалением
клавиатуры.

## Вывод и оставшиеся границы

- Клиентская проверка `/help`, обычного текста, переноса длинного ответа,
  HTML-formatting probe, отображения inline-кнопки и удаления клавиатуры
  зафиксирована выше.
- Командное меню осталось неоткрытым при пустых списках трёх проверенных scopes;
  scopes не менялись.
- HTML-разметка проверена только отдельным probe с `parse_mode=HTML` и не
  включена в штатный Telegram-адаптер.
- Callback event/payload и `answerCallbackQuery` остаются непроверенными.
- Вторую часть длинного ответа пришлось отправить повторно после неподтверждённой отправки;
  успешная итоговая доставка API и пользовательское отображение подтверждены.
- Production polling пока не восстановлен по просьбе владельца. Переключение
  считается эксплуатационно незавершённым до отдельного указания владельца о
  возврате. Не запускать автоматический таймер возврата.

В материалы проекта не включались токены, полный Bot API URL, пользовательские
ID, необработанные update/API-тела или содержимое переписки.
