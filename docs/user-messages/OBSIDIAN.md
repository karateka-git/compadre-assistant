# Obsidian: действующие сценарии и сообщения

Этот реестр помогает проверить путь пользователя от входа в Obsidian до
подключения хранилища и решения по статье. Правила написания ответов находятся
в [USER_MESSAGES.md](../USER_MESSAGES.md), практические команды — в
[RUN.md](../RUN.md). Здесь зафиксированы действующие шаблоны, а не целевая
редакция: `{…}` обозначает подставляемые данные, многоточие — опущенную часть
ответа. Оформление и доступность кнопок зависят от канала; текстовый путь
сохраняется.

Источники: [каталог команд](../../compadre_assistant/capabilities/obsidian/presentation/commands.py),
[обработчик](../../compadre_assistant/capabilities/obsidian/presentation/processing.py),
[форматирование ответов](../../compadre_assistant/capabilities/obsidian/presentation/responses.py),
[типы результатов](../../compadre_assistant/capabilities/obsidian/presentation/results.py).
Далее ссылки на функции относятся к этим файлам. Условия допуска профиля,
доступности возможности и общие команды принадлежат ядру.

## Войти в режим и выбрать следующий шаг

`/obsidian` включает длительный режим конкретного чата. Аргумент
`/obsidian <text or URL>` сразу поступает в предметный обработчик; без
аргумента `ObsidianMessageHandler.enter` собирает инструкцию, состояние vault,
доступные ожидания и состояние GitHub-авторизации в один ответ.

| Условие | Ключевой текст | Следующий шаг |
| --- | --- | --- |
| Вход без аргумента | «Режим Obsidian включён.»; «Пришли ссылку на статью для анализа или ссылку на GitHub repository, чтобы подключить либо заменить хранилище заметок (vault). После ссылки на repository можно указать папку vault.» | Подключить repository либо отправить статью; `/exit` выходит из режима. |
| Vault не выбран | «Хранилище заметок (vault) не подключено. Пришли ссылку на GitHub repository, чтобы подключить его.» | Отправить ссылку на repository. |
| Vault выбран | «Подключено хранилище: {owner}/{repository}{, папка: root_path}. Пришли ссылку на статью для анализа или используй команды режима.» | Отправить статью или выполнить команду обслуживания. При доступном sync manager и отсутствии действий подтверждения может предлагаться «Проверить состояние vault» → `/vault_status`. |
| Есть предложения | «Ожидаю решения по предложению{ для заметки path}. Если в этом чате ожидает только одно действие Obsidian, ответь „да“, чтобы применить предложение, или „нет“, чтобы отменить его.» | Выбрать действие по правилам подтверждений ниже; для `skip` положительное решение завершает рассмотрение без записи. |
| Есть замена/отключение | «Ожидает подтверждения {замены/отключения} хранилища (ID {id}). Ожидание действует 10 минут с момента создания. Решение доступно только в исходном чате и при выборе проверяется повторно.» | Выполнить актуальную адресную команду. |
| GitHub не настроен | «Подключение GitHub сейчас недоступно: провайдер GitHub не настроен на сервере.» | Дождаться настройки сервера, затем повторить вход/ссылку. |
| LLM не настроен | «Анализ статей сейчас недоступен: провайдер LLM не настроен на сервере. Подключение vault и команды его обслуживания доступны отдельно, если настроен GitHub.» | Настроить vault независимо от анализа; анализ повторить после настройки LLM. |
| Неизвестная slash-команда | «Не знаю такой команды Obsidian. Вызови /help, чтобы посмотреть доступные в этом чате команды.» | Открыть `/help`. |
| Обычный текст без поддерживаемого URL | «Пришли ссылку на статью, чтобы я попробовал её сохранить.» | Отправить HTTP/HTTPS-ссылку. |

Каталог `help_sections()` содержит `/vault_status` — состояние локальной копии,
`/vault_sync` — проверка GitHub и синхронизация, `/vault_disconnect` — отключение
после подтверждения, `/reanalyze <article_id>` — повторный анализ. Контекстная
справка показывает предметные команды в активном Obsidian; полный каталог
не означает их доступность вне режима.

## Авторизовать GitHub и подключить vault

В режиме отправляется `https://github.com/owner/repository` либо
`https://github.com/owner/repository vault/path`. Путь задаётся относительно
корня repository; для корня он не нужен. Ссылка на GitHub в начале сообщения
распознаётся как выбор vault до обработки статьи.

Device Flow выдаёт страницу авторизации и одноразовый код. Источники:
`_start_github_connection`, `_complete_github_connection` в обработчике,
`_format_github_connect_response` и `_format_github_failure` в форматтере.

| Условие | Ключевой шаблон | Следующий шаг |
| --- | --- | --- |
| Нужна новая авторизация | «Чтобы проверить repository, авторизуй GitHub.»; «1. Открой страницу: {verification_uri}»; «2. Введи одноразовый код: {user_code}.» | Открыть страницу, ввести код. «После подтверждения бот проверит repository и продолжит подключение vault. Временный GitHub token не сохраняется.» |
| Код уже выдан здесь | «Авторизация GitHub ждёт подтверждения.» + та же страница и код | Завершить существующую авторизацию; бот продолжит проверку repository и подключение. |
| Авторизация ещё запускается, включая отсутствие данных кода | «Авторизация GitHub запускается. Подожди несколько секунд, затем повтори ссылку на repository, если подключение не продолжилось.» | Подождать; при отсутствии продолжения повторить ссылку. |
| Авторизация в другом связанном канале | «Авторизация GitHub уже выполняется в другом связанном канале.» | Завершить её там либо дождаться истечения кода и снова прислать ссылку. |
| GitHub авторизован | «GitHub авторизован. Проверяю repository и начинаю первую синхронизацию vault. Дождись следующего сообщения с результатом.» | Дождаться результата; сама авторизация ещё не подтверждает успешную синхронизацию. |
| Пользователь отказал | «Авторизация GitHub отклонена; repository не подключён. Чтобы начать заново, снова пришли ссылку на repository.» | Повторить ссылку для новой попытки. |
| Код истёк | «Срок одноразового кода GitHub истёк, поэтому авторизация не завершена.» | Снова прислать ссылку для нового кода. |
| Ошибка начала | «Не удалось начать авторизацию GitHub. Снова пришли ссылку на repository, чтобы повторить запрос.» | Повторить ссылку. |
| Ошибка завершения | «Не удалось завершить авторизацию GitHub; подключение vault не продолжено.» | Повторить ссылку для новой авторизации. |
| Аккаунт авторизован, App не имеет доступа | «Аккаунт GitHub авторизован, но GitHub App не имеет доступа к repository.» | Открыть настройки App (URL добавляется, если доступен), выбрать repository, выдать `Contents: read and write`, затем повторить ссылку. |

Выбор и замена выполняются через `_select_github_vault`, результат описывает
`_format_vault_selection`: `{owner}/{repository}, ветка {branch}, папка
{root_path или корень repository}`.

| Условие | Ключевой шаблон/эффект | Следующий шаг |
| --- | --- | --- |
| Неверный URL или путь | «Не удалось распознать ссылку или путь к vault. Пришли GitHub repository в одном из форматов:» + оба примера выше | Исправить ввод. |
| Путь отсутствует или это файл | «Папка vault не найдена или указанный путь ведёт не к папке.» | Проверить относительный путь и отправить ссылку снова. |
| Repository недоступен | «GitHub App не может читать и записывать этот repository.» | Проверить URL и права App `Contents: read and write`, затем повторить ссылку. |
| Проверка завершилась ошибкой | «Не удалось проверить GitHub repository. Повтори ссылку на repository позже.» | Повторить позже. |
| Нужна авторизация | «Чтобы продолжить подключение vault, авторизуй GitHub по инструкции в следующем сообщении.» | Пройти Device Flow. |
| Первое подключение | «Хранилище подключено: {описание}.» + «Первая синхронизация с GitHub: {результат}» | Проверить результат sync; затем отправить статью. |
| Выбран тот же vault | «Это хранилище уже подключено: {описание}.» | Продолжить работу; новая замена не требуется. |
| Выбран другой vault | «Подключить {описание} вместо текущего vault? При подтверждении текущее подключение и его локальные данные будут заменены; repository на GitHub не изменится.» | Подтвердить `replace` или отменить; ожидание 10 минут. |
| Замена подтверждена | «Хранилище заменено на {описание}.» + результат синхронизации | Проверить результат sync. |
| Замена отменена | «Замена отменена. Текущее подключение и его локальные данные сохранены: {описание}.» | Продолжить с прежним vault. |
| Нет ожидающей замены | «Нет ожидающей замены. Пришли ссылку на новый GitHub repository, чтобы запросить подключение или замену vault.» | Повторить исходную ссылку при необходимости. |
| Первая синхронизация не удалась | «Подключение vault сохранено, но первая синхронизация не завершилась. Повтори /vault_sync.» | Исправить причину и синхронизировать; подключение не нужно создавать заново. |

## Проверить и синхронизировать хранилище

`/vault_status` показывает выбранный repository, ветку, папку, число локальных
заметок и файлов правил, последнюю проверку и успешную синхронизацию в UTC.
Если дат нет, используются «ещё не проверялся» и «ещё не синхронизировался».
Это чтение состояния, а не новая проверка GitHub. Источники:
`_format_github_status`, `_format_vault_sync`, `_format_embedding_coverage`.

| Условие | Ключевой текст | Следующий шаг |
| --- | --- | --- |
| Vault отсутствует | «Хранилище заметок (vault) не подключено. Чтобы подключить его, пришли ссылку на GitHub repository.» | Подключить repository. |
| Синхронизация уже идёт | «Синхронизация vault с GitHub уже идёт. После завершения вызови /vault_status, чтобы проверить состояние локальной копии.» | Дождаться окончания и проверить статус. |
| Недавно проверяли (`FRESH`) | «GitHub проверялся недавно, поэтому новый запрос не выполнялся. В локальной копии: заметок {total_notes}. Файлов правил: {instruction_files}.» | Продолжить работу; ответ не утверждает, что GitHub проверен заново. |
| GitHub проверен, изменений нет (`UNCHANGED`) | «GitHub проверен: изменений для локальной копии нет.» + счётчики | Продолжить работу. |
| Локальная копия обновлена | «Локальная копия vault обновлена из GitHub. Заметок: всего {total}; скачано: {downloaded}; добавлено: {added}; обновлено: {updated}; удалено: {deleted}.» + число файлов правил | Продолжить работу, учитывая состояние индекса. |
| Итоговая сводка отсутствует | «Синхронизация vault завершилась, но подробная сводка недоступна. Вызови /vault_status, чтобы проверить состояние локальной копии.» | Выполнить `/vault_status`. |
| Ошибка sync | «Не удалось завершить синхронизацию vault с GitHub. Локальная копия не помечена как актуальная; её содержимое могло не обновиться. Повтори /vault_sync позже.» | Повторить позже. |
| Нет конфигурации/файла правил, либо конфигурация неверна | «Не найден обязательный файл конфигурации {path}.» / «Не найден обязательный файл правил {path}.» / «{path} заполнен некорректно.» | Ответ добавляет YAML-пример: создать/исправить файл вручную, затем `/vault_sync`. При первой синхронизации отдельно говорится «Подключение сохранено». |
| Semantic index не настроен | «Семантический индекс не настроен. Поиск использует текстовый индекс FTS.» | Можно работать через полнотекстовый поиск. |
| Semantic index готов | «Семантический индекс готов: embeddings {embedded} из {total}.» | Дополнительного действия нет; sync может добавить числа добавленных и переиспользованных embeddings. |
| Покрытие частичное или индекс неактуален | «Семантический индекс ещё обрабатывается: embeddings {embedded} из {total}, осталось chunks {missing}. Пока индекс не готов, поиск работает через FTS fallback.» | Можно продолжить через FTS; состояние проверить командой `/vault_status`, обновление повторить `/vault_sync`. Текст не гарантирует отдельный фоновый процесс достройки. |

Обязательный файл правил и пример определяются
[конфигурацией vault](../../compadre_assistant/capabilities/obsidian/domain/vaults/vault_configuration.py)
и [загрузчиком примера](../../compadre_assistant/capabilities/obsidian/presentation/vault_configuration.py);
не подменять их копией примера в реестре.

## Отключить vault

`/vault_disconnect` запрашивает подтверждение `disconnect` в исходном чате:
«Отключить хранилище {owner}/{repository}? При подтверждении локальные
Markdown-файлы и связанные metadata будут удалены. Repository на GitHub не
изменится; профиль, связанные каналы, статьи и анализы сохранятся.»
Ожидание действует 10 минут. Для единственного ожидающего действия Obsidian
можно ответить «да»/«нет», для конкретного действия — использовать адресную
команду. Источники: `_request_vault_disconnect` и ветви `GITHUB_DISCONNECT_*`.

После согласия: «Vault отключён. Локальные Markdown-файлы удалены; repository
на GitHub не изменён. Профиль, связанные каналы, статьи и анализы сохранены.»
После отказа: «Отключение отменено. Текущий vault и его локальная копия сохранены.»
Если запроса нет: «Нет запроса на отключение vault. Вызови /vault_disconnect,
чтобы запросить отключение.» При отсутствии vault показывается инструкция
подключения, а не новое ожидание.

## Обработать статью и повторить анализ

HTTP/HTTPS-ссылка в режиме запускает сохранение и анализ при доступных vault и
LLM. Для долгой обработки используется квитанция «Принял, обрабатываю. Это
может занять немного времени.» из
[общих ответов](../../compadre_assistant/core/presentation/responses.py).
Квитанция не означает успех; итог фонового выполнения доставляется по
сохранённому адресу исходного чата. Обработка и повторы описаны в
`_process_article_url`, `_reanalyze_article`, `_run_reanalyze_article` обработчика.

| Условие | Ключевой шаблон | Следующий шаг |
| --- | --- | --- |
| Нет vault | «{имя}, хранилище заметок (vault) не подключено. Пришли ссылку на GitHub repository, чтобы подключить его.» | Подключить vault до обработки статьи. |
| Та же статья уже обрабатывается | «Эта статья уже обрабатывается. Повтори команду после завершения.» (для `/reanalyze`) | Дождаться обработки; не запускать параллельный повтор той же статьи. |
| Статья сохранена/обновлена/уже была | «Готово: статья сохранена.» / «Готово: статья обновлена.» / «Эта статья уже была сохранена.» | При отсутствии анализа результат содержит название, статус, ID статьи и длину текста; сохранить ID для повторного анализа. |
| Анализ новый/сохранённый | «Анализ готов.» / «Использую сохранённый анализ.» | Прочитать название, ID и текст анализа; если подготовлен proposal, перейти к решению. |
| Анализ не удался | «Статью удалось сохранить, но анализ пока не получился. Попробуй отправить ссылку позже.» | Повторить ссылку позже. |
| Proposal не подготовлен | «Анализ статьи сохранён, но подготовить предложение для Obsidian не удалось. Хранилище не изменено. Попробуй позже.» | Позже отправить статью на рассмотрение снова. |
| Результат уже применён | «Эта статья уже рассмотрена: {создана/обновлена} заметка {path}. Commit: {sha}. Страница повторно не загружалась, анализ заново не запускался.» | Прочитать сохранённый результат; при `skip` вместо пути/commit выводятся решение не менять vault и причина. Сохранённый анализ добавляется, если доступен. |
| Ошибка нормализации URL | «Не удалось разобрать ссылку. Проверь URL и пришли его еще раз.» | Исправить URL. |
| Ошибка загрузки | «Не удалось загрузить страницу по ссылке. Проверь, что она открывается в браузере, или попробуй позже.» | Проверить страницу или повторить позже. |
| Не извлечён текст | «Страница загрузилась, но текст статьи извлечь не получилось. Можно попробовать другую ссылку на эту же публикацию.» | Отправить другую ссылку. |
| Ошибка хранения/иная обработка | «Не удалось сохранить статью. Попробуй позже.» / «Не удалось обработать ссылку. Отправь её ещё раз позже.» | Повторить позже. |
| Данные итоговой сводки отсутствуют | «Статья обработана, но результат не удалось подготовить.» / «Анализ готов, но результат не удалось подготовить.» / «Анализ обновлен, но результат не удалось подготовить.» | Проверить результат повторным запросом позже; эти ответы не содержат готовой сводки. |

Для сохранённой статьи `/reanalyze <article_id>` заново получает статью и
принудительно запускает анализ. Без ID, при подключённом сервисе ожидаемого
ввода, `/reanalyze` отвечает: «Укажи числовой ID статьи для повторного анализа.
Ожидание действует 10 минут. Для отмены введи /cancel.» Следующее сообщение
принимается как ID. Неверное значение не продлевает исходный срок.

| Условие повторного анализа | Ответ/проверка | Следующий шаг |
| --- | --- | --- |
| Неверный аргумент прямой команды | «Для повторного анализа нужен числовой ID статьи. Используй /reanalyze <article_id>.» | Передать десятичный ASCII ID в диапазоне SQLite. |
| Неверное значение в пошаговом вводе | «Не удалось распознать ID статьи. Введи числовой ID или отмени ввод командой /cancel. Ожидание ID продолжается.» | Исправить ID или отменить. |
| Статья чужая/недоступна | «Статья недоступна в этом профиле.»; в пошаговом вводе добавляется «Введи другой ID или отмени ввод командой /cancel.» | Выбрать доступную статью; пошаговый ввод остаётся открытым. |
| Есть активное действие статьи | «Для этой статьи уже ожидается действие. Заверши его в исходном чате перед повторным анализом.» | Завершить прежнее действие. В пошаговом вводе дополнительно «Ожидание ID продолжается.» |
| Успех без proposal | «Анализ обновлён. Название: {title}. ID статьи: {id}.» + анализ | Прочитать результат. При наличии proposal вместо этого показывается предложение. |
| Ошибка | «Не удалось обновить анализ статьи. Проверь ID статьи или попробуй позже.» | Проверить ID/повторить позже. |

До принятия ID повторно проверяются профиль, доступность возможности и режим
чата. Смена контекста прекращает ожидание; ID не передаётся другой возможности.
Поведение подтверждают [тесты пошагового ввода](../../tests/test_capability_pending_input.py).

При автоматической проверке GitHub обработка может использовать пригодный
локальный снимок. `_with_vault_sync_warning` добавляет одно из сообщений:
«Хранилище сейчас синхронизируется в другом связанном канале. Для этой операции
использована текущая локальная копия.»; «Не удалось обновить хранилище из
GitHub. Использована последняя локальная копия.»; «Заметки и полнотекстовый
индекс актуальны, но семантический поиск временно недоступен. Поиск выполнен
через полнотекстовый поиск (FTS fallback).» Дополнительно выводятся число
локальных заметок и, при наличии, последняя успешная проверка GitHub в UTC.
После восстановления доступен `/vault_sync`. Отсутствие пригодного снимка
или обязательной конфигурации нельзя трактовать как разрешение такого fallback.

## Рассмотреть предложение и подтвердить действие

`_format_obsidian_review` показывает действие, причину, путь и предпросмотр.
`add` предлагает «создать новую заметку» и «Предлагаемый текст заметки»;
`update` — «обновить существующую заметку» и «Предлагаемый diff» (при отсутствии
diff используется подготовленный Markdown). Предпросмотр ограничен первыми
2000 символами и может завершаться «[Предпросмотр сокращён.]».
Текст, путь и анализ остаются буквальными данными, не доверенной разметкой.

Для `add`/`update`: «Хранилище пока не изменено. Если в этом чате ожидает только
одно действие Obsidian, ответь „да“, чтобы применить предложение, или „нет“,
чтобы отменить его.» Для `skip`: «Анализ готов. Предлагаю не менять хранилище.
Причина: {reasoning}» и предложение ответить «да», чтобы завершить рассмотрение
без изменений, либо «нет», чтобы отменить предложение.

Положительное решение `add`/`update` записывает изменение прямым GitHub commit;
положительное `skip` только завершает рассмотрение. Отмена сохраняет vault
неизменным. `_operation_actions` создаёт для каждого pending-действия пару:

```text
/confirm obsidian proposal <id> <version> yes
/confirm obsidian proposal <id> <version> no
/confirm obsidian replace <id> <version> yes
/confirm obsidian replace <id> <version> no
/confirm obsidian disconnect <id> <version> yes
/confirm obsidian disconnect <id> <version> no
```

Пользователь копирует команду из актуального ответа, а не подбирает ID или
версию. `/confirm` без аргументов только показывает текущие действия через
ядро. Короткие ответы `да`, `нет`, `yes`, `no`, `y`, `n` без учёта регистра
принимаются только для единственного действия Obsidian в исходном чате и
при полном снимке ожиданий; пользовательская подсказка использует «да»/«нет».
Несколько ожиданий требуют адресной команды. Проверки профиля, исходного
канала/чата, статуса, ID и версии выполняются сервером заново при решении.
**Наличие текста команды или кнопки не означает клиентскую проверку её
актуальности и не разрешает обход серверных проверок.**

Предложения статьи не имеют срока ожидания решения. Замена и отключение vault
имеют срок по умолчанию 10 минут. Lease выполнения записи не является сроком
ожидания proposal. Источники:
[сервис подтверждений proposal](../../compadre_assistant/capabilities/obsidian/domain/reviews/confirmation.py),
[выбор vault](../../compadre_assistant/capabilities/obsidian/domain/vaults/vault_selection.py),
[проверки снимка и срока](../../tests/test_confirmation_snapshot.py).

| Результат/ограничение | Ключевой текст | Следующий шаг |
| --- | --- | --- |
| Предложение отменено | «Предложение отменено. Хранилище не изменено; статью можно отправить на новое рассмотрение.» | При необходимости отправить статью снова. |
| Подтверждён `skip` | «Рассмотрение завершено. Хранилище не изменено.» | Действие завершено. |
| Запись успешна | «Изменение записано в GitHub прямым commit. Путь: {path}. Commit: {sha}.» | Действие завершено. |
| Запись успешна, индекс не обновился | «Заметка записана в GitHub, но поисковый индекс ещё не обновлён. Запусти /vault_sync, чтобы обновить его.» | Запустить sync; не считать commit неудачным. |
| Vault изменился после подготовки | «Хранилище изменилось после подготовки предложения, поэтому запись отменена и чужие изменения не перезаписаны.» | Снова отправить ссылку для предложения по актуальной версии. |
| Vault занят | «Хранилище сейчас занято синхронизацией или записью из другого связанного канала. Предложение сохранено.» | После окончания операции подтвердить повтор или отменить; короткое решение только при единственном ожидании. |
| Ошибка записи | «Не удалось записать изменение в GitHub. Предложение и текст статьи сохранены.» | После устранения причины повторить решение или отменить. |
| Нет сводки предложения | «Предложение для Obsidian подготовлено, но сводка недоступна.» | Получить актуальное состояние через `/obsidian` прежде чем выбирать действие. |
| Нет действия для короткого ответа | «В этом чате нет действия Obsidian, которое можно подтвердить. Чтобы посмотреть команды режима, вызови /help.» | Открыть справку/создать нужное действие. |
| Несколько действий | «Есть несколько ожидающих действий, поэтому ответ „да“ или „нет“ неоднозначен. Выбери нужное действие точной командой /confirm из его ответа; команда содержит ID и версию.» | Выполнить команду нужного действия. |
| Снимок ожиданий неполон | «Не удалось получить полный список действий Obsidian. Ответ „да“ или „нет“ не обработан.» | Повторить позже либо использовать точную адресную команду актуального запроса. |
| Неверная адресная команда | `Используй /confirm obsidian <proposal\|replace\|disconnect> <id> <version> <yes\|no>.` | Скопировать полную команду; ID и версия — положительные десятичные ASCII-числа в диапазоне SQLite. |
| Служба подтверждения недоступна | «Служба подтверждений Obsidian недоступна. Действие не обработано; повтори точную команду /confirm после восстановления службы.» | Повторить после восстановления. |
| Другой исходный чат | «Заверши действие в исходном чате; операция здесь недоступна.» | Вернуться в исходный чат. |
| Proposal устарел | «Это действие устарело. Вызови /obsidian в нужном чате, чтобы получить актуальное состояние.» | Получить текущее состояние. |
| Конфигурационное ожидание устарело/истекло, vault изменился или занят | Обработчик передаёт предметное сообщение `PendingOperationError` / `VaultResourceBusyError` | При истечении повторить исходную ссылку или `/vault_disconnect`; при занятости дождаться освобождения; при существующем ожидании решить его в исходном чате. |
