# Сообщения ядра

Этот реестр описывает действующие ответы ядра для регистрации, профиля, связи каналов, выбора возможностей, справки, меню, ожиданий и подтверждений. По условию и ответу можно определить следующий шаг пользователя. Общие правила текста и доставки приведены в [USER_MESSAGES.md](../USER_MESSAGES.md), команды для пользователя — в [RUN.md](../RUN.md#13-посмотреть-доступные-команды). Формулировки ниже сверены с кодом в текущей ветке; переменные в `{фигурных скобках}` означают подстановку, а не буквальный текст ответа.

Источники: [каталог команд](../../compadre_assistant/core/presentation/incoming/commands.py), [диспетчер](../../compadre_assistant/core/presentation/incoming/dispatcher.py), [контекстная справка](../../compadre_assistant/core/presentation/incoming/help.py), [меню](../../compadre_assistant/core/presentation/incoming/menu.py), [ожидание ввода](../../compadre_assistant/core/presentation/incoming/pending_input.py), [форматтер ответов](../../compadre_assistant/core/presentation/responses.py). Сценарии проверяются в [тестах справки](../../tests/test_contextual_help.py), [пошагового ввода ядра](../../tests/test_core_pending_input.py) и [меню](../../tests/test_command_menu.py).

## Создать профиль и назвать его

1. В неизвестном канале `/start` отвечает: «Compadre Assistant запущен. Этот канал пока не зарегистрирован. Отправь `/register`, чтобы создать нового пользователя, или `/link <code>`, чтобы привязать этот канал к уже существующему пользователю. Все команды: `/help`». Другая команда, требующая профиля, отвечает: «Я пока не знаю этот канал. Отправь `/register`, чтобы создать нового пользователя, или `/link <code>`, чтобы привязать этот канал к уже существующему пользователю». Следующий шаг — регистрация или привязка канала.
2. `/register` без аргументов в неизвестном канале **ещё не создаёт профиль**. Ответ: «Как к тебе обращаться? Пришли имя или название профиля. Профиль будет создан после принятия имени; ожидание действует 10 минут. Для отмены введи `/cancel`». Пользователь отправляет имя следующим сообщением в том же чате. `/register <name>` отклоняется: «Используй `/register` без аргументов. Имя нужно отправить следующим сообщением».
3. Если имя допустимо, ответ: «Приятно познакомиться, {имя}. Регистрация завершена. {подсказка доступных входов}. Команды: /help». Профиль и связь канала созданы; пользователь может выбрать доступную возможность. Если имя не принято, ответ: «Имя не принято. Используй от 1 до 80 символов без ссылки или команды. Отправь исправленное имя ещё раз; для отмены введи `/cancel`». Исходное ожидание продолжается без продления срока. При ошибке завершения регистрации ожидание снимается и предлагается «Не удалось завершить регистрацию. Повтори /register».
4. Повтор `/register` при готовом профиле отвечает: «{имя}, ты уже зарегистрирован. {подсказка доступных входов}». `/start` отвечает: «Compadre Assistant запущен. Рад тебя видеть, {имя}. {подсказка доступных входов}». Следующий шаг нужен только для входа в возможность.
5. `/name` без аргумента просит: «Пришли новое имя профиля. Ожидание действует 10 минут. Для отмены введи /cancel». `/name <name>` применяет имя сразу. Успех: «Готово. Теперь буду обращаться к тебе: {имя}». При неверном имени в ожидании можно отправить исправленное значение или `/cancel`; при прямой команде ответ указывает правило «от 1 до 80 символов без ссылки или команды» и пример `/name Влад`, после чего команду нужно повторить. Смена имени не меняет режим чата.

## Привязать второй канал и решить конфликт

1. В уже привязанном канале `/link_code` выдаёт «Код привязки: {код}. Открой другой канал и отправь: `/link {код}`. Код действует 10 минут». Если код создать не удалось: «Не удалось создать код привязки. Попробуй позже». Следующий шаг после успеха — открыть другой канал и ввести код до истечения срока.
2. В другом канале `/link <code>` применяет код сразу. `/link` без аргумента отвечает: «Пришли код привязки следующим сообщением. Ожидание действует 10 минут. Для отмены введи /cancel». Код можно отправить следующим сообщением в том же чате. При успешной связи: «Готово, я привязал этот канал к твоему пользователю».
3. При неверном или истёкшем коде прямой вызов отвечает: «Код привязки не принят. Повтори /link <code> с действующим кодом. Если истёк сам код, получи новый через `/link_code` в уже привязанном канале; код действует 10 минут». В активном ожидании ответ предлагает отправить исправленный код до его срока или `/cancel`; если истёк сам код, нужен новый `/link_code`. Неудачная попытка в ожидании не продлевает его. Если канал уже связан с тем же профилем: «Этот канал уже привязан к пользователю».
4. Если канал связан с другим профилем, ответ сообщает: «Канал уже привязан к другому профилю. Подтверди перенос адресной командой». Он содержит действия «Перенести identity: `/confirm core identity {id} {version} yes`» и «Отменить: `/confirm core identity {id} {version} no`». Решение отправляют из исходного чата до истечения подтверждения. Простые `да` и `нет` перенос не выполняют. При подтверждении: «Готово, я перепривязал этот канал», при известном имени добавляется «Теперь он связан с профилем «{имя}»». При отказе: «Ок, оставляю текущую привязку без изменений».
5. Неверная форма адресной команды отвечает: «Используй адресную команду из актуального запроса привязки». При устаревшем действии: «Это действие устарело или истекло. Повтори /link в исходном чате, чтобы получить актуальные команды». Повторное действие начинается с нового кода или команды по указанному условию; старое подтверждение не исполняется.

## Посмотреть профиль, выбрать возможность и режим

- `/status` показывает «Профиль: {имя}. Режим этого чата: {id или не выбран}. {подсказка доступных входов}». Для лично выключенного или серверно недоступного сохранённого режима добавляется причина. Пользователь может выбрать вход или вызвать `/exit`.
- `/capabilities` показывает каждый известный ID и описание с состояниями «Личный выбор: включена/выключена; сервер: доступна/недоступна». Затем предлагает `/enable` или `/disable` для пошагового выбора либо `/enable <id>` и `/disable <id>` для прямого вызова. Личный выбор действует во всех привязанных каналах. При пустом каталоге выводится «Сейчас нет известных возможностей». Аргумент у `/capabilities` отклоняется с просьбой вызвать команду без аргументов; неизвестному каналу предлагается `/register`.
- `/enable` предлагает только доступные на сервере и лично выключенные возможности; `/disable` — лично включённые. Ответ перечисляет ID и описания, срок ожидания 10 минут и `/cancel`. Когда вариантов нет, ответы: «Нет возможностей, которые можно включить. Посмотри /capabilities» или «Нет включённых возможностей. Посмотри /capabilities». Прямые формы принимают ровно один ID. Несколько ID, неизвестный ID и серверная недоступность дают причину и следующий шаг; при ожидании можно исправить ID без продления срока или ввести `/cancel`. Ошибка сохранения: «Не удалось сохранить выбор. Попробуй позже». Успех: «Возможность {id} [уже] включена/выключена. Выбор действует во всех привязанных каналах. Режим и данные сохранены».
- Вызов лично выключенного входа отвечает: «Возможность {id} лично выключена. Включить: /enable {id}. Список: /capabilities». Для недоступного на сервере входа: «Возможность {id} недоступна на сервере. Список: /capabilities». Ранее показанные справка и кнопка не заменяют повторную проверку доступа.
- Обычный текст без выбранного режима получает подсказку доступных входов и `/capabilities`, `/help`; при отсутствии входов — «Сейчас нет включённых возможностей». Сохранённый, но недоступный режим получает причину, доступные входы и `/exit`. `/exit` очищает режим только этого чата и отвечает: «Режим этого чата завершён. {подсказка доступных входов}. Команды: /help». Ошибка входа предлагает повторить позже или `/help`; ошибка обработки в режиме просит проверить состояние действия перед повторной отправкой. Вложение без текста получает: «Пришли текстовое сообщение или выбери возможность через /help».

## Открыть контекстную справку и меню

`/help` начинается с «Compadre Assistant — справка». Содержание зависит от профиля, сохранённого режима, доступных возможностей и проверенных ожиданий конкретного чата:

| Состояние | Что показывается и что делать дальше |
| --- | --- |
| Профиля нет | `/register`, `/link` и прямой путь `/link <code>`. При ожидании имени вместо этих входов показываются «Регистрация не завершена. Как к тебе обращаться? Пришли имя или название профиля» и `/cancel`. |
| Профиль есть, активного постоянного режима нет | Разделы «Основные», «Связь Telegram и VK», «Личные возможности» с командами из публичного каталога; затем эффективные входы или «Сейчас нет доступных возможностей». Ask обозначен как одноразовый вопрос без смены режима. Из каталога исключены общие `/cancel` и `/confirm`, пока нет соответствующего состояния. |
| Активен постоянный режим | Публичные команды и инструкции этой возможности, `/exit`, общие `/status`, `/capabilities`, `/link_code`; для полной общей справки предложено `/exit`, затем `/help`. Доступный Ask показан как одноразовый вход. Скрытые команды других возможностей в этот список не попадают. |
| Сохранённый режим недоступен | Причина: лично выключена либо недоступна на сервере; `/exit`, общие команды и альтернативные эффективные входы. Для сохранённого одноразового Ask сообщается, что такой постоянный режим устарел. |

Проверенное ожидание добавляет «Ожидается {значение}. Отправь значение следующим сообщением» и `/cancel`. Просроченный, сменивший владельца или недоступный ввод не предлагается. Актуальные подтверждения выводятся отдельным блоком. Просмотр справки сам по себе не принимает значение и не выполняет подтверждение.

Меню строится из того же проверенного состояния. До регистрации оно содержит `/register`, `/link`; при ожидании регистрационного имени — только `/cancel`. В основном режиме меню предлагает общие команды и эффективные входы, в постоянном режиме — публичные команды этой возможности, `/exit` и доступный одноразовый Ask. `/cancel` появляется при активном ожидании; `/confirm` — лишь при полном снимке с актуальными действиями у зарегистрированного пользователя. Команды с обязательным аргументом без пошагового пути не добавляются как пустые заготовки. Меню и кнопки являются подсказками: полный текст команды можно ввести вручную, а исполнение повторно проверяет профиль, чат и доступ. [Тесты меню](../../tests/test_command_menu.py) и [его обновления](../../tests/test_menu_lifecycle.py) фиксируют эти переходы.

## Продолжить или отменить ожидаемый ввод

Общее ожидание создаётся командами `/register`, `/link`, `/name`, `/enable`, `/disable` без аргумента, когда для последней пары есть варианты. Оно принадлежит исходному каналу и чату, хранится в памяти процесса 10 минут и не продлевается после неверного значения. `/help`, `/status`, `/capabilities`, `/start` сохраняют ожидание. Другая slash-команда заменяет или отменяет его перед обычной обработкой; прямые команды с аргументом исполняются как новые действия. Смена профиля канала, режима или доступа владельца отменяет неприменимое ожидание.

`/cancel` без аргументов снимает ввод и отвечает: «Ввод отменён. Активный режим этого чата не изменён». Без ожидания: «В этом чате нечего отменять. Продолжай текущий режим или вызови нужную команду». С аргументами команда просит использовать `/cancel` без аргументов. После истечения обычный текст не принимается как значение: «Срок ожидания ввода истёк. Повтори {команда}, чтобы начать заново». Следующая команда обрабатывается обычным порядком. При неизвестном исходе внешнего действия ввод закрывается с ответом «Не удалось обработать ввод. Проверь состояние действия перед повторной отправкой».

## Посмотреть и выполнить подтверждение

`/confirm` без аргументов только читает актуальные действия исходного чата. Полный непустой снимок отвечает «Доступные действия:» и показывает подпись с **полной адресной командой для каждого решения**; после этого пользователь вводит выбранную команду. Полный пустой снимок отвечает: «В этом чате нет действий, которые нужно подтвердить». Если часть источников недоступна, известные действия показываются с предупреждением «Список действий неполный: часть источников подтверждений недоступна»; если действий не удалось получить, ответ: «Не удалось получить полный список действий для подтверждения. Попробуй позже». Голая `/confirm` при неполном снимке не предлагается в меню или справке как путь выбора.

Подтверждения возможности доступны только из применимого активного режима. Если адресная команда относится к другому режиму, ответ предлагает войти через соответствующую команду в исходном чате; при недоступном входе показывает доступные варианты. Для переноса канала действуют только точные `/confirm core identity {id} {version} yes` и `/confirm core identity {id} {version} no`. Просмотр `/confirm` и `/help` не выполняет решение. Источники: [диспетчер](../../compadre_assistant/core/presentation/incoming/dispatcher.py) и [тесты справки](../../tests/test_contextual_help.py).
