# Сообщения ядра

Этот реестр описывает действующие ответы ядра для регистрации, профиля, связи каналов, выбора возможностей, справки, меню, ожиданий и подтверждений. По условию и ответу можно определить следующий шаг пользователя. Общие правила текста и доставки приведены в [USER_MESSAGES.md](../USER_MESSAGES.md), команды для пользователя — в [RUN.md](../RUN.md#13-посмотреть-доступные-команды). Формулировки ниже сверены с кодом в текущей ветке; переменные в `{фигурных скобках}` означают подстановку, а не буквальный текст ответа.

Источники: [каталог команд](../../compadre_assistant/core/presentation/incoming/commands.py), [диспетчер](../../compadre_assistant/core/presentation/incoming/dispatcher.py), [контекстная справка](../../compadre_assistant/core/presentation/incoming/help.py), [меню](../../compadre_assistant/core/presentation/incoming/menu.py), [ожидание ввода](../../compadre_assistant/core/presentation/incoming/pending_input.py), [форматтер ответов](../../compadre_assistant/core/presentation/responses.py). Сценарии проверяются в [тестах справки](../../tests/test_contextual_help.py), [пошагового ввода ядра](../../tests/test_core_pending_input.py) и [меню](../../tests/test_command_menu.py).

## Создать профиль и назвать его

1. В неизвестном канале `/start` отвечает: «Compadre Assistant запущен. Этот канал пока не зарегистрирован. Отправь `/register`, чтобы создать нового пользователя, или `/link <code>`, чтобы привязать этот канал к уже существующему пользователю. Все команды: `/help`». Другая команда, требующая профиля, отвечает: «Я пока не знаю этот канал. Отправь `/register`, чтобы создать нового пользователя, или `/link <code>`, чтобы привязать этот канал к уже существующему пользователю». Следующий шаг — регистрация или привязка канала.
2. `/register` без аргументов в неизвестном канале **ещё не создаёт профиль**. Ответ: «Как к тебе обращаться? Пришли имя или название профиля. Профиль будет создан после принятия имени; ожидание действует 10 минут. Для отмены введи `/cancel`». Пользователь отправляет имя следующим сообщением в том же чате. `/register <name>` отклоняется: «Используй `/register` без аргументов. Имя нужно отправить следующим сообщением».
3. Если имя допустимо, ответ: «Приятно познакомиться, {имя}. Регистрация завершена. {подсказка доступных входов}». Профиль и связь канала созданы; пользователь может выбрать доступную возможность. Если имя не принято, ответ: «Имя не принято. Используй от 1 до 80 символов без ссылки или команды. Отправь исправленное имя ещё раз; для отмены введи `/cancel`». Исходное ожидание продолжается без продления срока. При ошибке завершения регистрации ожидание снимается и предлагается «Не удалось завершить регистрацию. Повтори /register».
4. Повтор `/register` при готовом профиле отвечает: «{имя}, ты уже зарегистрирован. {подсказка доступных входов}». `/start` отвечает: «Compadre Assistant запущен. Рад тебя видеть, {имя}. {подсказка доступных входов}». Следующий шаг нужен только для входа в возможность.
5. В режиме `/settings` команда `/name` без аргумента просит: «Пришли новое имя профиля. Ожидание действует 10 минут. Для отмены введи /cancel». `/name <name>` применяет имя сразу. Успех: «Готово. Теперь буду обращаться к тебе: {имя}». При неверном имени в ожидании можно отправить исправленное значение или `/cancel`; при прямой команде ответ указывает правило «от 1 до 80 символов без ссылки или команды» и пример `/name Влад`, после чего команду нужно повторить. Смена имени не меняет режим чата.

## Привязать второй канал и решить конфликт

В штатной сборке `/link_code`, `/link` и решения о переносе профиля принимаются
в подтверждённом личном чате Telegram или VK. В другом чате бот отвечает
«Для привязки профиля открой личный чат с ботом».

1. В уже привязанном канале открой `/settings`. Команда `/link_code` выдаёт код, точную команду `/link {код}` для другого канала и напоминание открыть там `/settings`, если профиль уже есть. Код действует 10 минут. Если код создать не удалось: «Не удалось создать код привязки. Попробуй позже».
2. В новом канале `/link <code>` доступна до регистрации и применяет код сразу. Если в другом канале уже есть профиль, открой там `/settings` перед `/link`. `/link` без аргумента отвечает: «Пришли код привязки следующим сообщением. Ожидание действует 10 минут. Для отмены введи /cancel». Код можно отправить следующим сообщением в том же чате. При успешной связи: «Готово, я привязал этот канал к твоему пользователю».
3. При неверном или истёкшем коде прямой вызов предлагает повторить `/link <code>` с действующим кодом. Если код истёк, в уже привязанном канале нужно открыть `/settings` и вызвать `/link_code`. При ожидаемом вводе можно отправить исправленный код или `/cancel`. Неудачная попытка не продлевает ожидание. Если канал уже связан с тем же профилем: «Этот канал уже привязан к пользователю».
4. Если канал связан с другим профилем, ответ сообщает: «Канал уже привязан к другому профилю. Подтверди перенос адресной командой». Он содержит действия «Перенести identity: `/confirm core identity {id} {version} yes`» и «Отменить: `/confirm core identity {id} {version} no`». Решение отправляют из исходного чата до истечения подтверждения. Простые `да` и `нет` перенос не выполняют. При подтверждении: «Готово, я перепривязал этот канал», при известном имени добавляется «Теперь он связан с профилем «{имя}»». При отказе: «Ок, оставляю текущую привязку без изменений».
5. Неверная форма адресной команды отвечает: «Используй адресную команду из актуального запроса привязки». При устаревшем действии: «Это действие устарело или истекло. В исходном чате открой `/settings` и повтори `/link`».

## Посмотреть профиль, выбрать возможность и режим

`/settings` открывает режим настроек текущего чата. Ответ показывает имя профиля и команды для изменения имени, привязки канала и управления возможностями. `/help` показывает полный список команд режима. `/exit` возвращает на главную. Ввод команды настроек из другого режима предлагает сначала открыть `/settings`.

- `/status` в настройках показывает профиль, текущий режим и доступные входы.
- `/capabilities` показывает видимые профилю возможности, их ID для ручного ввода и состояния «Личный выбор: включена/выключена; сервер: доступна/недоступна». Для режима ИИ строка начинается с «Режим ИИ» (ai). Бот предлагает `/enable` или `/disable` для пошагового выбора либо `/enable <id>` и `/disable <id>` для прямого вызова. Личный выбор действует во всех привязанных каналах. Настройки доступны каждому зарегистрированному профилю и не входят в личный выбор. `/enable settings` и `/disable settings` отвечают «Личный доступ к возможности «Настройки» нельзя изменить». При пустом каталоге выводится «Сейчас нет известных возможностей». Аргумент у `/capabilities` отклоняется с просьбой вызвать команду без аргументов. Незнакомому каналу бот предлагает `/register`.
- `/enable` предлагает только доступные на сервере и лично выключенные возможности. `/disable` показывает лично включённые. Для возможности с публичным названием бот показывает название и полную команду, а на кнопке пишет, например, «Включить «Режим ИИ»». Для остальных возможностей список содержит ID и описание. Ожидание действует 10 минут, отмена доступна через `/cancel`. Когда вариантов нет, бот предлагает `/capabilities`. Прямые формы принимают ровно один ID. Несколько ID, неизвестный ID и серверная недоступность дают причину и следующий шаг. При ожидании можно исправить ID без продления срока или ввести `/cancel`. При ошибке сохранения бот отвечает «Не удалось сохранить выбор. Попробуй позже».
- Вызов лично выключенного входа отвечает: «Возможность {id} лично выключена. Включить: /settings, затем /enable {id}». Для недоступного на сервере входа: «Возможность {id} недоступна на сервере. Список: /settings, затем /capabilities». При исполнении ядро заново проверяет доступ.
- При заданном отображаемом названии подтверждения и отказы показывают его в кавычках. Успешное включение отвечает «Личный доступ к возможности «{название}» [уже] включён. Выбор действует во всех привязанных каналах». Отключение и подтверждения для возможностей без публичного названия используют «Возможность {название или id} [уже] включена/выключена. Выбор действует во всех привязанных каналах. Режим и данные сохранены». Для режима ИИ см. [порядок входа](AI.md#войти-в-режим-ии).
- Возможность с доверенным доступом появляется в списках допущенного профиля. Прямой вызов без права отвечает «У твоего профиля нет доступа к этой возможности». После отзыва права `/help` скрывает сохранённый режим, а `/enable` и `/disable` отклоняют скрытый ID как неизвестный. Для Admin также нужен личный чат.
- Обычный текст без выбранного режима получает подсказку доступных входов и `/help`. Сохранённый видимый режим, который недоступен, получает причину, доступные входы и `/exit`. `/exit` очищает режим этого чата и отвечает: «Режим этого чата завершён. {подсказка доступных входов}». Ошибка входа предлагает повторить позже или `/help`. Ошибка обработки в режиме просит проверить состояние действия перед повторной отправкой. Вложение без текста получает: «Пришли текстовое сообщение или выбери возможность через /help».

## Открыть контекстную справку и меню

`/help` начинается с «Compadre Assistant — справка». Содержание зависит от профиля, сохранённого режима, доступных возможностей и проверенных ожиданий конкретного чата:

| Состояние | Что показывается и что делать дальше |
| --- | --- |
| Профиля нет | `/register`, `/link` и прямой путь `/link <code>`. При ожидании имени вместо этих входов показываются «Регистрация не завершена. Как к тебе обращаться? Пришли имя или название профиля» и `/cancel`. |
| Профиль есть, активного постоянного режима нет | Доступные входы, в том числе `/settings`. `/cancel` и `/confirm` появляются при соответствующем состоянии. |
| Активен постоянный режим | Публичные команды и инструкции этой возможности, например `/ask` в режиме ИИ или `/name`, `/capabilities`, `/link_code` в настройках, и `/exit`. Для полной общей справки предложено `/exit`, затем `/help`. Также показываются доступные зарегистрированные одноразовые входы. |
| Сохранённый режим недоступен | Для видимого профилю и чату режима справка показывает причину отключения, `/exit` и альтернативные входы. Для сохранённого режима одноразовой возможности сообщается, что режим устарел. |

Проверенное ожидание добавляет «Ожидается {значение}. Отправь значение следующим сообщением» и `/cancel`. Просроченный, сменивший владельца или недоступный ввод не предлагается. Актуальные подтверждения выводятся отдельным блоком. Просмотр справки сам по себе не принимает значение и не выполняет подтверждение.

Меню строится из того же проверенного состояния. До регистрации оно содержит
`/register` и `/link`. При ожидании регистрационного имени доступна только
`/cancel`. На главной меню предлагает только доступные входы и действия по
текущим ожиданиям. `/start` и `/help` можно ввести вручную.
В постоянном режиме оно показывает публичные команды режима, `/exit` и
доступные зарегистрированные одноразовые входы. `/cancel` появляется при
активном ожидании, а `/confirm` при полном снимке с актуальными действиями
у зарегистрированного пользователя. Команды с обязательным аргументом без
пошагового ввода остаются в справке. Полный текст команды можно ввести
вручную. Исполнение повторно проверяет профиль, чат и доступ.
[Тесты меню](../../tests/test_command_menu.py) и [его обновления](../../tests/test_menu_lifecycle.py).

Если введена команда доступной возможности вне её режима, ядро отвечает
«Чтобы выполнить команду, войди в режим через {команда входа}.» Затем
введи команду входа в этом чате и повтори действие. Если возможность
выключена, ядро объясняет причину отказа.

## Продолжить или отменить ожидаемый ввод

Общее ожидание создаётся командами `/register` и `/link` до регистрации либо командами `/link`, `/name`, `/enable`, `/disable` в настройках. Для `/enable` и `/disable` должны быть доступны варианты. Команда вызывается без аргумента. Оно принадлежит исходному каналу и чату, хранится в памяти процесса 10 минут и не продлевается после неверного значения. `/help`, `/status`, `/capabilities`, `/start` сохраняют ожидание. Другая slash-команда заменяет или отменяет его перед обычной обработкой; прямые команды с аргументом исполняются как новые действия. Смена профиля канала, режима или доступа владельца отменяет неприменимое ожидание.

`/cancel` без аргументов снимает ввод и отвечает: «Ввод отменён. Активный режим этого чата не изменён». Без ожидания: «В этом чате нечего отменять. Продолжай текущий режим или вызови нужную команду». С аргументами команда просит использовать `/cancel` без аргументов. После истечения обычный текст не принимается как значение: «Срок ожидания ввода истёк. Повтори {команда}, чтобы начать заново». Следующая команда обрабатывается обычным порядком. При неизвестном исходе внешнего действия ввод закрывается с ответом «Не удалось обработать ввод. Проверь состояние действия перед повторной отправкой».

Пока бот обрабатывает принятый вопрос или фото, на входящие команды, сообщения и кнопки
в этом чате он отвечает «Обработка уже идёт. Дождись результата или введи
/cancel.» без выполнения этих входов. `/cancel` без аргументов от автора запроса
сразу освобождает чат с ответом «Обработка отменена. Активный режим этого чата
не изменён.». Пока чат занят, в меню есть только `/cancel`. В Telegram
после освобождения чата меню отразит текущий режим и доступ. В VK
изменившееся нижнее меню приходит с содержательным сообщением в этом чате.
Освобождение чата без результата оставляет показанное меню. При следующей
команде бот заново проверит состояние и доступ. Отменённый результат в чат
не отправляется.

## Посмотреть и выполнить подтверждение

`/confirm` без аргументов только читает актуальные действия исходного чата. Полный непустой снимок отвечает «Доступные действия:» и показывает подпись с **полной адресной командой для каждого решения**; после этого пользователь вводит выбранную команду. Полный пустой снимок отвечает: «В этом чате нет действий, которые нужно подтвердить». Если часть источников недоступна, известные действия показываются с предупреждением «Список действий неполный: часть источников подтверждений недоступна»; если действий не удалось получить, ответ: «Не удалось получить полный список действий для подтверждения. Попробуй позже». Голая `/confirm` при неполном снимке не предлагается в меню или справке как путь выбора.

Подтверждения возможности доступны только из применимого активного режима. Если адресная команда относится к другому режиму, ответ предлагает войти через соответствующую команду в исходном чате; при недоступном входе показывает доступные варианты. Для переноса канала действуют только точные `/confirm core identity {id} {version} yes` и `/confirm core identity {id} {version} no`. Просмотр `/confirm` и `/help` не выполняет решение. Источники: [диспетчер](../../compadre_assistant/core/presentation/incoming/dispatcher.py) и [тесты справки](../../tests/test_contextual_help.py).
