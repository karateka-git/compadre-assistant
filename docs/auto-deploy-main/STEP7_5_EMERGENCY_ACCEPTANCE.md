# Шаг 7.5: приёмка аварийного маршрута и независимых релизов

Статус на 20.10.2026: локальная реализация и изолированная приёмка выполнены.
Шаг **не закрыт** до переноса в `release/1.0` через PR #35 и полного CI
точного release merge SHA. Адресный rerun одной линии, многолинейный fan-out
и гонка с pending run подтверждены в GitHub.
Устаревший systemd drop-in удалён в согласованном окне 20.10.2026.
Настоящий аварийный Release для испытания не создавался.

## Правило выпуска

Выбранные `release/X.Y` независимы. Взаимные полные URL в описаниях PR
позволяют проследить исправление; состояние PR другой линии не блокирует
слияние, публикацию или развёртывание текущей. Исправление обязательно
должно быть в `main`: через слитый PR либо достижимый существующий commit.
Собственный release PR перед выпуском должен быть слит в выпускаемую ветку.

После слияния main PR доверенный workflow обрабатывает все связанные
открытые release PR. Успешный `hotfix-deps` пропускается; для отсутствующего
в API run/job и выполняющегося `pr-fast`/`hotfix-deps` предусмотрено ожидание
с общим бюджетом 240 секунд и интервалом опроса до 5 секунд. Все готовые
линии обрабатываются до паузы. Текущий failed job перезапускается после
повторной проверки SHA, целевой ветки, описания, состояния PR, main и latest job.
Отказ одной линии не препятствует обработке остальных;
workflow сообщает совокупную ошибку после обработки группы. Merge другой
релизной линии больше не запускает rerun. Auto-merge остаётся собственным
решением для каждого PR и требует всех обязательных checks.

Сохранены проверки репозитория, взаимных URL, main, точного candidate,
истории PR текущей линии, защищённого тега, неизменяемого Release и версии.
Обычная публикация требует полный CI. Аварийная допускает непрошедший CI
с причиной и аудитом; backup, совместимость схемы и безопасный возврат
этим разрешением не отключаются.

## Локальные доказательства

Команда из изолированной рабочей копии:

```powershell
$env:PYTHONUTF8='1'
& C:/Users/compadre/Documents/obsChatBot/.venv/Scripts/python.exe -m unittest tests.test_emergency_end_to_end tests.test_publish_emergency_release tests.test_publish_release tests.test_select_deploy_release tests.test_deploy_prod tests.test_check_hotfix_pairs tests.test_rerun_hotfix_deps -q
```

Результат: 101 тест, 100 успешны, один пропущен на Windows (проверка реального
Linux/systemd). Fake API/host не подтверждают работу GitHub или production.
Все пять YAML workflow разобраны `yaml.safe_load`; `git diff --check` прошёл.

| Проверка | Фактическое доказательство |
| --- | --- |
| Новая линия без полного CI | `test_emergency_end_to_end`: локальный Git → аварийная публикация через fake API → серверный selector → успешное переключение fake host; обычный путь отвергает аварийный Release. |
| PATCH с новым main PR и с существующим main commit | Тот же модуль проходит оба варианта, проверяет пары/commit, манифест и причины; неуспешный candidate возвращает оба канала на прежний образ. |
| Другой релиз ещё не слит | `test_check_hotfix_pairs` допускает `check_pr` обеих линий после main и обычный/аварийный `check_release` текущей линии; E2E подтверждает аварийный selector и успешное развёртывание при открытом PR другой линии. |
| Нет main или commit недостижим | `test_check_hotfix_pairs` блокирует release PR и оба вида публикации; E2E selector отвергает недостижимый main commit. Чужие URL, отсутствие взаимных ссылок и изменение описания также закрывают допуск. |
| Зелёная/failed/изменившаяся линия | `test_rerun_hotfix_deps` пропускает зелёную, посылает POST только failed job, отвергает изменившийся PR; отдельный тест доказывает продолжение после отказа первой линии. |
| Main merge до завершения release pr-fast | `test_rerun_hotfix_deps` проверяет ожидание отсутствующего run/job и выполняющейся проверки, готовую вторую линию до паузы, переход pending → failed/green, общий timeout без POST, изменение снимка во время ожидания и замену latest job перед POST. |
| Ошибка selector или новая миграция | `test_deploy_prod` фиксирует `failed_preflight`, прежний checkout/образ и отсутствие остановки writers; для миграции сохраняется причина и нет marker. |
| Ошибка backup либо миграции | Оба канала возвращаются на старый образ, state `rolled_back`, timer восстановлен, marker снят; сохранены инициатор, причины публикации/запуска, точный SHA и состояния CI. При backup fault миграции не запускаются. |
| Неудачный возврат | State `degraded`, оба канала остановлены, timer выключен, backup и marker сохранены. Повторная попытка не меняет действия или аудит. |
| Старый тег при более новой вершине ветки | Selector принимает доказанный `ahead` без несуществующего `head_commit`; `diverged` и неверный merge-base отклоняются. |
| Systemd без старого 90 | Полная `Host.installed` проверка допускает отсутствие файла после обновления загруженных DropInPaths; устаревший загруженный список отвергается. |

Ранее созданный локальный коммит `8c46848` не переносится целиком: его

серверный selector не получает ошибочную межрелизную блокировку.

## Оставшийся GitHub gate

Перенести изменение в поддерживаемую `release/1.0` через PR #35 после
явного разрешения и проверить полный `release-full` точного merge SHA.
Затем записать результат и cleanup временных ресурсов. Настоящий аварийный
Release для испытания не нужен.

Ограничение: после истечения общего бюджета ожидания workflow завершается
ошибкой с номерами незавершённых линий. Когда их актуальный run завершится,
оператор повторяет доверенный workflow либо адресный failed job, сверив
текущий PR и main. Completion-trigger за пределами бюджета отсутствует;
весь workflow также ограничен 10 минутами, включая запросы GitHub API.
